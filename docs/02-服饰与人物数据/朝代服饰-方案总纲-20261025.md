# 定妆间 · 朝代服饰与左栏改造 · 方案总纲

> 日期：2026-10-25
> 范围：左栏「人物参数」信息架构 + 新增「朝代/阶级服饰」模块
> 结论一句话：方向对，但要把「族群 / 时代 / 阶级」拆成三件事；清装不要做成「一个阶级下拉 + 每个阶级一套衣服」，而要做「身份卡 × 场合 × 槽位」的造型模式；并且先修左栏，再上清装。

---

## 1. 我理解的需求（先复述）

现状：定妆间已经跑通「随机人物 → 结构化提示词 → 生图 → 自动存档」。左栏 73 项参数、317 个选项、7 个分组，塞在 284px 宽的栏里；右侧 16 个内容段 + 4 个结构段，5 个画幅；生图接口只支持文生图。

你想做四件事：

1. **左栏太密**：想让它更好用，不要一屏只看到 4 项参数、改一项要滚 5.8 屏。
2. **加「亚裔（先中国附近的）」这个维度**：把现在的「东亚/东南亚/南亚/西亚」往具体文化圈推进。
3. **加朝代，先做清朝**：而且不是只做一套清装，要按阶级（皇帝、官员、士、商、农、仆役……）各出服饰。
4. **先确认逻辑对不对**：有没有没想到的、更成熟的做法，并要一份清朝服饰调研。

我按这个理解往下写。如果第 2 条你其实只是想要「更细的亚洲人脸型/骨相」，而不是「朝代」，那它应该走另外一条线（见 2.2），不要和清装混在一起。

## 2. 逻辑体检：哪些对，哪些要改

### 2.1 对的部分

- **服装确实是这个产品的下一阶段。** README 第 273 行已经写明「JSON 是以后加朝代服装的依据」；docs/02-服饰与人物数据/人物参数调研-20261022.md 第 7 节把「服装拆解、主题色卡」列为后续候选。现在做，是顺着原计划走。
- **用清朝做第一站是对的。** 清代服饰是中国历代里制度最严密、存世实物与图像最多、轮廓辨识度最高的一档；对文生图模型来说，「补服、顶戴、马蹄袖、朝珠、旗头」这些词在训练数据里出现频率高，比唐宋更不容易画成「影楼古装」。
- **按阶级做也是对的。** 清代冠服的本质就是用衣服标明身份等级（《大清会典》把它写成法律），所以「阶级/身份」不是装饰性分类，而是这套服饰系统的主键。这一点你的直觉很准。

### 2.2 需要拆开的三组概念

**（1）族群 ≠ 时代 ≠ 阶级。** 这是三个正交维度：

- 族群/地域：决定骨相、肤色、五官基底（现在的 ethnicity 只干这个）。
- 时代/文化圈：决定发型、首服、衣制、鞋履、纹样、颜色制度，甚至姓名与身份词库。
- 阶级/身份：决定「在这个时代里，你能穿什么、不能穿什么」。

现在的 ethnicity 只有 4 个泛亚裔选项；如果你把「清朝」塞进族群，会出现「东亚 + 清」这种范畴错误——清不是民族，也不是族群。**正确做法：新增独立的「时代（era）/ 文化包（culture pack）」上下文，族群保持只影响脸。** 这样以后加「日本江户、朝鲜王朝、越南阮朝」时，是加一个文化包，而不是把每个参数再复制一遍。

**（2）阶级 ≠ 品级 ≠ 职业。** 「清朝各阶级」至少有四层含义，做 UI 前要选清楚：

- 制度等级：皇帝、宗室、异姓爵、文官 1–9 品、武官 1–9 品、未入流、命妇；
- 社会身份：士（举贡监生员）、农、工、商、僧道、仆役、优伶、皂隶、乐户；
- 旗籍/民族：满洲、蒙古、汉军、汉人；旗女与汉女的女装是两套；
- 场合：朝服、吉服、常服、行服、便服、丧服、婚服。

同一个「官员」，朝服和常服是两套完全不同的画法；同一个「贵妇」，旗女和汉女是两套；同一个「平民」，男女、婚丧又不同。**所以「阶级」不能是一个下拉框直接映射到一套衣服，至少要「身份 × 场合 × 性别/旗汉」三个坐标。**

**（3）朝代 ≠ 一套衣服。** 清朝 268 年，从顺康到同光，男辫由「金钱鼠尾」变粗、女旗头从两把头到晚期大拉翅、晚清出现捐官、西式呢料、新军、照相馆混搭。**必须选时间锚点**：建议先做「盛清（乾隆—嘉庆）」一个断面，UI 上写明「清 · 盛清」，不要笼统写「清朝」。而且**单品也有年代**：大拉翅是光绪以后、高底鞋（花盆底/马蹄底）道光以后、氅衣/衬衣也是晚清流行——**盛清卡不要用这些单品**，否则「清装」内部就自相矛盾。P1 锁盛清时，旗女用两把头/钿子 + 袍/褂 + 平底旗鞋；花盆底/大拉翅/氅衣放 P2 的「清末」卡。

### 2.3 三个硬冲突（不先解决，做出来会互相打架）

**冲突一：素体 vs 穿衣。** 现在整套产品是「素体设定稿」：男上身赤裸、女/中性肉色抹胸 + 紧身短裤，靠这个看清体型，也顺带规避裸露审核（README「素体遮挡」；web/app.js:441-444 把 underTop 写死）。一旦穿上补服/氅衣：

- 体型参数被袍服遮住，「正背卡」原本的用途（看骨架/体量）就失效了；
- 如果同一张图里又想露又想穿，模型会画出「补服下面露出抹胸」这种废图。

**结论：必须做「双模式」——素体卡（现有，保留）/ 造型卡（新增）。** 不是在同一张卡里既脱又穿。underTop、outfitExtra 这两个硬编码常量要抽成 coverageVars(sex, era)。

**冲突二：发型/胡须 vs 剃发留辫。** 现有 15 种发型、5 种胡须（狼尾、半束、络腮胡……）是「现代/泛古风」语义。清代男性必须剃发结辫，旗女是两把头/钿子，汉女是髻。用户如果选「清装 + 狼尾」，提示词会自相矛盾。

**结论：时代要能「接管」某些参数**——不是删掉，而是在清装模式下把这些项置灰、锁定或改写，并在 UI 上说明「被首服接管」。同理：旗人男性不蓄大胡、旗女不缠足、清装下纹身/花臂默认关闭。

**冲突三：提示词预算已经到顶。** 现在 npm run check 的输出：

- 正背设定卡 2095 / 2100 字
- 三视图 2097 / 2100 字
- 全身立绘 1764 / 1800
- 半身肖像 1761 / 1800
- 表情九宫格 1793 / 1800

**正背卡只剩 5 个字。** 清装 9 个槽位若写成压缩句（4 张卡实测 66～74 字/张），净增约 +77 字；若再带负向段，净增约 +113 字。可行路径：先把 negative/layout/realism/info 四段里重复的话删掉（可腾 −52～−125 字），再把预算分档改成「素体 1800/2100、清装 1900/2200」。这样横版落在 2047～2083 字，留 17～53 字余量，而不是无脑抬到 2600。

### 2.4 一个顺序问题：先修左栏，再上清装

左栏现在：**整栏滚动内容约 7,399px ≈ 11.6 屏，1440×900 首屏只完整看到 4 项参数（5.5%）**；其中词句行占 1,656px（22.4%）、选项按钮 317 个、常驻工具按钮 219 个。

如果现在直接加 9 个服饰槽位：按现状全展开约 **+1,100～1,300px**，整栏到 8,500px（13.4 屏）；而按「摘要行」形态只 +330px。**所以 IA 改造不是和清装并行的两件事，而是清装的前置条件。** 先做 1–2 天能验证的 P0，再上数据。

## 3. 左栏：从「73 项平铺」到可用

详细诊断与三套方案见 docs/01-规划与实施/左栏信息架构-改造方案-20261025.md（下称「IA 文档」）。这里只给结论。

### 3.1 五个可测的数字（现状 → 目标）

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 左栏滚动内容 | 7,399px（11.6 屏） | ≤ 2,900px（约 4.5 屏） |
| 首屏完整可见参数 | 4 / 73 | ≥ 12 / 73 |
| 词句行占高 | 1,656px（22.4%） | 0（并入摘要行） |
| 整栏 DOM / 常驻按钮 | 约 2,100 / 536 | ≤ 1,200 / ≤ 120 |
| 改一项的平均滚动 | 5.8 屏 | ≤ 1 屏（其余走搜索/定位） |

### 3.2 推荐：A「渐进披露」为主，吸收 B 的检查器、预留 C 的上下文条

- **A（1.5–2 人日）**：默认一行摘要（名称 + 当前值 + 状态点），点名称就地展开选项；点值 chip 弹浮层，**改值仍是 1 次点击**；保留「全展开」密度档作为逃生舱。
- **B 的精华（0.5 天）**：把现有「参数详情」弹窗变成可点击改值（现在 .pd-row 是只读 div，看完说明还得关窗再找选项，3 次点击）。
- **C 的入口（0.5 天）**：左栏顶部预留一行上下文条「时代 ▾ / 身份 ▾」，为清装占位；完整「人 / 装 / 时代」三模式留到 P2。

另外三条低成本高收益的修复（IA 文档 S4/S5/M2）：

- 修「折叠/筛选状态下从右栏点变量定位静默失败」；
- 搜索防抖 + 折叠组内命中强制展开 + 显示命中数；
- 默认只显示「核心 31 项」，进阶 42 项一键切换（现在默认「全部」）。

### 3.3 清装进来后左栏长什么样

- 人模式只多 **1 行 31px**（「服饰 清·文官三品 · 9 槽 ›」），点进去才是 9 个槽位；
- 9 个槽位按摘要行算 +330px，而不是 +1,100px；
- 被接管的毛发/纹身等项显示「被首服接管」角标，不静默消失。

## 4. 服饰：数据与交互怎么搭

### 4.1 本体

    era/culture（时代/文化包）
      └ rank/role（身份/等级：帝后、宗室、文官、武官、命妇、士、商、农、工、役、僧道、旗女、汉女…）
          └ occasion（场合：朝 / 吉 / 常 / 行 / 便 / 婚 / 丧）
              └ slots（槽位：首服 / 外衣 / 内搭 / 下装 / 鞋 / 配饰 / 纹样 / 质料 / 色）

- **族群只留在 ethnicity**，不参与朝代。
- **时代是「包裹」不是「并列」**：它能禁掉别的分组里的选项（如清装男性禁用狼尾），所以要做成上下文，而不是第 8 个平铺分组。
- **身份卡（archetype）** 是最小可卖单位：一张卡 = 一个身份 + 一个场合 + 9 个槽位 + 一组参数修正 + 一段提示词。

### 4.2 九槽位（MVP）

| 槽 | 说明 | 清装示例 |
| --- | --- | --- |
| 首服 | 冠/帽/头饰 | 朝冠、吉服冠、暖帽、凉帽、瓜皮帽、钿子、两把头 |
| 外衣 | 最外层 | 补褂、蟒袍、龙袍、氅衣、衬衣、马褂、坎肩 |
| 内搭 | 中衣/衬衣 | 白布中衣、立领衬衣、纱衫 |
| 下装 | 裙/裤/行裳 | 朝裙、马面裙、衬裤、行裳 |
| 鞋 | 靴/鞋 | 皂靴、布鞋、花盆底、马蹄底 |
| 配饰 | 佩挂 | 朝珠、荷包、扳指、指甲套、扇 |
| 纹样 | 补子/蟒/团花 | 文官补子、武官补子、团龙、暗八仙 |
| 质料 | 面料 | 妆花缎、暗花绸、纱、皮毛、棉布 |
| 色 | 主色 | 石青、绛红、月白、香色、明黄（受限） |

### 4.3 条件门控 + 预设覆盖（不要往 options 里堆）

现在的 params.json 是「全局选项 + 分性别权重」。清装不要给每个参数加「清朝选项」，否则 73×N 爆炸。推荐三层（新增 2 组、73→85 项、317→360 选项即可）：

1. **选项级门控**：给选项加 g:{era, culture, rank, occasion}，只改 weightOf() 一行（gateOk 返回 0），置灰/随机/clamp 三处自动一致。
2. **身份卡预设**：一张卡写入 9 槽 + 若干参数值 + deny/allow 规则，类似现有画幅 vars，但作用于参数（applyEraPreset）。
3. **冲突规则**：复用 data/params.json 的 conflictRules（when/fix），补「era=qing & hairStyle=wolf → 辫发」「补子禽兽 vs 品级」「明黄 vs 非帝后」等。

### 4.4 提示词与画幅

- 新增三段：costume（形制：首服/外衣/内搭/下装/鞋/配饰）、costumeMake（纹样/质料/色）、costumeNeg（时代/阶级负向），不要塞进现有 31 字的 outfit 段；era=none 时三段为空串，编译时自动丢弃，不占素体预算。
- underTop / outfitExtra 抽成 coverageVars(sex, era)；版面裁切句拆成新变量 frameCrop，解决 layouts.json 里 vars.outfitExtra 会整句覆盖服饰描述的问题（半身像/九宫格现在就是这么干的）。
- 预算分档：素体卡维持 1800/2100；清装卡 1900/2200——2200 只是**上限缓冲**，靠腾挪后实际落在 2047～2083，不追求用满，更不再另设 2600 档；并在 check-prompt 里按时代断言。
- 新增「服饰拆解 / 色卡」画幅（参考 人物资产图_布局调研 的第 3、4 类骨架）：三视图 + 补子/袖口/鞋/面料微距 + 色卡。这是最能证明「考据做对了」的版式。
- 半身像/九宫格只到胸口，**不要描述下装和鞋**；按画幅 suppress 槽位。

### 4.5 存档与一致性

- 存档 JSON 升 v4：加 character.context {era, rank, occasion}、slots、presetId、sourceRefs；**不要改现有「男/女/中性」目录结构**，只加字段，老图照常可读。
- 「换一个」要在当前时代/身份内随机；「锁」能锁槽位；「记忆点」可扩展到造型（如「补子仙鹤」）。
- 目前上游只支持文生图（server.mjs:390 只发 model/prompt/n/size/quality，没有图生图/种子），多视图的服装一致性只能靠提示词写死结构 + 降低细节野心；真正的「同角色换装」留到有图生图能力时再做。

### 4.6 校验与测试

- validate-data：era/rank 合法组合、槽位齐全、选项门控字段、每个新参数必须被内容段引用（现有规则）、禁止跨时代混搭。
- check-prompt：清装档预算、被 suppress 的槽位不得出现、补子/首服/鞋必须成组出现。
- test-layouts：加「切换时代/身份卡 → 参数与提示词同步」「老存档读入不炸」，以及一条专门防泄漏的：「清装态手改 costume 段 → 切回素体态，提示词里不得出现服饰句」。

### 4.7 清装上线前必须补的 6 个界面接线（约 0.5 天）

三段服饰正文都只挂一个复合变量（如 {{costume}}），9 个槽位参数不在任何段文本里。映射的**单一出口放在数据里**——`data/templates.json` 的内容段加可选字段 `covers:[…]`（app 的 `loadData`、`validate-data`、`check-prompt` 三端同读同一份，避免各自复制粘贴漂移；`app.js` 是浏览器普通脚本，不能 import `scripts/`）。app 侧用 `coversOf()/expandComposite()` 接 4 处。如果不补下面 6 处，清装模式第一眼就是「9 行全灰 + 体检 9 个错」：

| # | 位置 | 不改的症状 | 改法 |
| --- | --- | --- | --- |
| 1 | usedVarKeys（app.js:573） | 9 个槽位全被标「未用」并变灰 | expandComposite(used)：命中 {{costume}} 时把 covers 里的 9 个槽位 id 一并算已用；但**要加「编译后非空」条件**——清装态把 9 槽全设「无」时 costume 返回空串、段被丢弃，此时不能把 9 行标成已用 |
| 2 | collectHealthIssues（app.js:1412） | 体检报「9 个参数未接入」 | 判 notIntegrated 前先查 covers，并注意「空串段不算引用」（素体态别误标已用）；体检要按 era 上下文过滤——era=none 时不该常驻报 9 条 |
| 3 | openParamDetail（app.js:1303） | 详情写「没有任何内容段引用，数据待修」 | 显示「经 {{costume}} 间接写进服饰形制段」 |
| 4 | varMetaFor / CANVAS_VARS（app.js:542/512） | 变量表里 costume/costumeMake/costumeNeg/frameCrop 显示「未定义」且点不动 | 加 4 条表项，source 指向左栏服饰 / 当前版面 |
| 5 | ensureBlockSkeleton（app.js:1623） | 素体态右栏凭空多 3 个永远为空的段（16→19） | 内容段加 when:{era:[…]}，renderBlocks 复现有「本画幅不用」样式折叠标「本时代不用」；段保留不删（删了切时代又补、存档会漂）。**编译层必须把 when 做成与 suppress 同级的 blockOff 守卫**（compilePrompt / compilePromptHTML / usedVarKeys / blockVarUsage / updatePromptPreview 五个调用点），textarea.readOnly（app.js:2031 现在没有守卫）只是第二道体验闸——因为 text 可编辑且持久化，手改过的清装段切回素体后文字仍非空，compilePrompt 的 trim 拦不住 |
| 6 | check-prompt.mjs:57-58 | 脚本里还有一份 underTop/outfitExtra 硬编码副本，校验的提示词与 App 实际产出的不是同一份 | 抽 scripts/app-sandbox.mjs（纯 ESM、vm 截函数），check 与 test-layouts 共用；同时把 133 行 indexOf("下身只穿") 的旧锚点换成 frameCrop/清装态锚点 |

这 6 处必须排在「清装组落地」之前，否则功能是通的、界面看起来像坏了。第 5 条尤其别只做样式：`when` 段如果只 CSS 折叠、textarea 还能编辑、编译层也不过滤，用户手打的字会直接拼进提示词——这是「界面看起来对、发出去的提示词是错的」，比灰行更难查。正确的层次是**编译层守卫（真闸）+ 编辑层只读（体验闸）**；只做 readOnly 会漏掉「清装态手改 → 切回素体」这条持久化泄漏路径。另一条实现细节：`covers` / `when` 挂在 `DATA.content[id]` 上按段 id 读即可，**不必进 `state.blocks`**，所以旧 localStorage 不需要迁移，`defaultBlocks` / `ensureBlockSkeleton` 也不用改字段。

## 5. 清代：考据要点（先给结论，细表见调研文档）

> 说明：A=官修典制，B=博物馆实物，C=图像，D=近人研究/笔记，E=民俗/影视。下面凡标「待核」的，都需要在正式数据里二次核对。

### 5.1 坐标系

性别 × 旗汉（满/蒙/汉军/汉人）× 身份等级 × 场合 × 季节。**顺序不能反**：先定「谁」，再定「什么场合」，最后才是「穿哪套」。

### 5.2 身份清单（做数据时的枚举，不是 UI 标签）

帝后（皇帝/太后/皇后/妃嫔）；宗室（亲王/郡王/贝勒/贝子/公/将军）；异姓爵（公侯伯子男/额驸）；文官 1–9 品 + 未入流；武官 1–9 品；命妇；士（举人/贡生/监生/生员）；民（农/工/商）；仆役/皂隶/优伶/乐户/水户；僧道；旗兵/闲散；孩童；晚清新军/学堂/买办。

### 5.3 三张硬表

**（1）补子（A/B，故宫博物院藏品页）**

| --- | --- | --- |
| 一品 | 仙鹤 | 麒麟 |
| 二品 | 锦鸡 | 狮 |
| 三品 | 孔雀 | 豹 |
| 四品 | 云雁 | 虎 |
| 五品 | 白鹇 | 熊 |
| 六品 | 鹭鸶 | 彪 |
| 七品 | 鸂鶒 | 犀 |
| 八品 | 鹌鹑 | 犀 |
| 九品 | 练雀 | 海马 |

补充：都御史/按察使等用獬豸；公、侯、伯用蟒补（A，康熙会典）；**王公用圆形团龙/团蟒，文武官用方形补子**（前后各一方，乾隆实物约 28.5cm 见方——不是巨大胸甲）；命妇补子随夫/子品级，且**武官母妻用鸟纹、不用兽纹**。「补子上的禽兽种类」是模型最容易画错的地方，提示词不要要求画到羽毛级别，写「方形补子，中央绣一只展翅仙鹤，四周祥云」即可。武七品补子「犀牛」与「彪」两说并存（《清史稿》与《大清律例》均 A 级），建议先采「犀牛」并在数据里标待核。

| 品级 | 顶珠（顺治定制） |
| --- | --- |
| 一品 | 红宝石 |
| 二品 | 珊瑚 |
| 三品 | 蓝宝石 |

补充：雍正八年起用同色玻璃替代宝石，乾隆以后七品以下素金顶多用黄铜；花翎/蓝翎另有一套（五品以上孔雀花翎、六品以下蓝翎；贝子三眼花翎、公双眼花翎——D，《啸亭续录》），**不是按品级简单一一对应**，生图时不要给每个官员都插花翎。

**（3）朝珠（A/B，故宫「青金石朝珠」页）**

- 文官五品、武官四品以上可佩；命妇受封五品以上同。
- 绦带：帝后明黄，其他人金黄或石青。
- 材质：东珠（皇帝/皇后，大典礼用）、青金石、珊瑚、蜜蜡、翡翠、琥珀等，按身份与场合（祀天青金石、祀地蜜珀、朝日珊瑚、夕月绿松石）。
- 常见错误：把朝珠画成短项链、没有佛头/背云/记念、人人可戴。

### 5.4 服色与材质禁令（A，《大清会典》冠服通例原文）

- 崇德元年：亲王以下官民人等，不用黄色及五爪龙凤、黄缎。
- 顺治八年：一应朝服、便服表里，不许用黄色、秋香色。
- 顺治九年：五爪/三爪龙缎、满翠缎团补、黄色、秋香色等，非上赐禁止；违者官议罚、常人鞭责。
- 康熙元年：公、侯伯、郡主、额驸用四爪蟒补；文官一品仙鹤补；武官一品麒麟补；军民人等不许用蟒缎、妆缎、金花缎、片金、倭缎、貂皮等。
- 康熙三年：文官四品以上用蟒服、挂数珠；五品以下不准。
- 康熙十一年：举人、贡生、监生、生员不许用貂皮、猞猁狲、白豹皮、蟒缎、妆缎、金花缎；军民、听差、书吏准用绸绫、纺绢、绵绸、葛苎、梭布、狼狐貉羊皮等。

**给提示词的启发**：清装不是「越华丽越对」，**「谁能用黄、谁能用蟒、谁能用貂」本身就是阶级信息**。生成平民时，要明确写「粗布/棉布/靛蓝/无纹样」，否则模型会自动加缎面和暗纹。

### 5.5 女装双轨

- **旗女**：袍服体系（衬衣、氅衣、大襟右衽、宽袖/马蹄袖）、首服（钿子、两把头；**大拉翅是光绪以后**）、旗鞋（花盆底/马蹄底，**道光以后才流行，清初旗女穿靴**）、耳饰「一耳三钳」。
- **汉女**：上衣下裙（袄、衫、马面裙）、披风、云肩、抹额、髻；命妇礼服有霞帔（清代演为阔如背心、下施流苏、中间缀补子），民间婚礼则「借服」凤冠霞帔（民俗，不是日常制度）。
- **「男从女不从」是民间说法，不是一条正式法令**：实际是汉族妇女较多保留了明代袄裙传统，同时旗汉女装在晚清互相影响。做数据时按「旗/汉」两条支线，不要写成政治口号。

### 5.6 发式与鞋

- 男：剃发留辫。清初「金钱鼠尾」式（只留脑后一小撮），后期辫子变粗、额前留发增多；**不要画成现代马尾/半披发**。
- 女：旗女两把头/钿子/大拉翅；汉女髻（牡丹头、平髻等）、抹额；少女双丫髻/辫。
- 鞋：官员黑缎皂靴；平民布鞋/草鞋（且不许穿缎靴）；旗女高底鞋（花盆底/马蹄底）**道光以后**才流行，清初旗女穿靴；汉女弓鞋（缠足，建议不生成，只做文字说明）。

### 5.7 晚清变化（如果做「清末」而不是「盛清」）

捐纳/捐官让商人可穿官服（但补子/顶戴按捐纳品级）；西式呢料、洋布、剪裁进入；新军 1905 后换西式军服；照相馆里出现「官服 + 西式背景」混搭。**「清末」和「康乾」不是一套数据**，建议先锁盛清。

### 5.8 AI 生图高频错误清单（验收时逐条打勾）

1. 所有女性都戴大拉翅（晚清才流行）。
2. 明黄/龙袍给官员、商人、平民。
3. 补子位置错（应在补褂前胸后背，方形；宗室为圆形团龙）。
4. 补子禽兽与品级错配（文官绣虎、武官绣鹤）。
5. 顶珠颜色/材质乱配；给所有官员插花翎。
6. 朝珠当项链、长度错、缺佛头/背云/记念。
7. 龙/蟒不分（五爪四爪 + 名分）。
8. 马蹄袖缺失或画成西式袖口。
9. 披领、领衣缺失（朝服）。
10. 开衩数/位置错（宗室与官员不同，待核）。
11. 马褂 / 马甲 / 坎肩混为一谈。
12. 瓜皮帽、暖帽、凉帽、官帽混戴；冒出宋明乌纱帽翅。
13. 明制交领、飞鱼服、乌纱帽混入。
14. 韩服/和服元素混入（尤其女装）。
15. 现代拉链、印花、亮片、影楼缎面；补褂是平袖，不要给所有衣服都加马蹄袖。
16. 男性不剃发/不结辫；女性披发、刘海。
17. 官靴画成现代皮靴/运动鞋；旗鞋画成高跟鞋。
18. 石青画成宝蓝/纯黑；明黄画成柠檬黄。
19. 补子糊成一块图案或写成文字。
20. 三视图之间补子/纹样/颜色漂移。

### 5.9 可直接拼进提示词的中文短句（样例）

- 正一品文官（常服/补服）：「清代盛期正一品文官，头戴暖帽，帽顶红宝石顶珠，身穿石青色补褂，前胸后背各一方形补子，补子中央绣展翅仙鹤与祥云，内穿蓝色长袍，颈挂朝珠，脚穿黑色皂靴，剃发留辫，长辫垂于背后。」
- 旗人贵妇（盛清·常服）：「清代中前期旗人贵妇，梳两把头、戴钿子，身穿藕荷色缎地长袍，外罩石青色坎肩，衣缘镶滚，脚穿平底旗鞋，耳戴一耳三钳。」（氅衣、衬衣、花盆底、大拉翅属晚清，放到 P2 的「清末」卡，不要混进盛清。）
- 汉人书生（常服）：「清代汉族书生，头戴黑色瓜皮帽，身穿靛蓝色长衫，外罩黑色马褂，白布袜、黑布鞋，剃发留辫，手持折扇。」
- 农妇（便服）：「清代汉族农妇，头发挽髻、包蓝布包头，身穿靛蓝粗布短袄，下穿深色布裤，系围裙，脚穿布鞋，面料为粗棉布，无纹样。」
- 商人（常服）：「清代商人，头戴瓜皮帽，身穿酱色暗花绸长袍，外罩黑缎马褂，腰间挂荷包，脚穿千层底布鞋。」

注意：**不要要求模型在衣服上写「衙」「兵」等字**，文字必糊；用颜色、短衣、腰带、帽子来表意。

### 5.10 三个数据决策（建议这样定）

1. **武七品补子**：《清史稿》作犀牛（八品如七品），《大清律例》条例作「与六品同」（即彪），两处都是 A 级官修文本。**建议先采「犀牛」**，数据里标「两说并存」，UI 不展开这个细节。
2. **schema 做四层，不做一级下拉**：朝代 → 性别/旗汉 → 品级/身份 → 场合。并且把**补子、顶珠、朝珠、花翎做成互斥校验组**：选「文一品」就锁「鹤 + 红宝石顶 + 有朝珠」；选「文七品」就锁「鸂鶒 + 素金顶 + 无朝珠」。这是目前模型最容易自由组合出错的地方。
3. **色名单独做「清代色名色卡」**：明黄/金黄/香色（秋香）/石青/宝蓝/藕荷/雪青，每个色名带色值 + 使用禁令元数据（谁能用、谁不能用）。不要用现代色名（如「宝蓝」）硬套，否则模型会画出荧光蓝。

### 5.11 敏感与边界

- 剃发易服、旗汉等级、缠足都是历史事实，但文案用中性描述，不做「野蛮/落后」式评价，不生成缠足细节。
- 龙纹、明黄、朝珠是等级符号，不是「越华丽越好」；生成平民时主动降级。
- 若以后接图生图，博物馆藏品图只能做参考，不能直接商用；来源要登记。

## 6. 路线图

| 阶段 | 内容 | 产出/验收 | 预估 |
| --- | --- | --- | --- |
| P0 | 左栏摘要行 + 值浮层 + 修定位 + 搜索防抖 + 详情可编辑 + 默认核心 | 滚动 ≤2,900px；首屏 ≥12 行；改值 1 次点击 | 2–3 天 |
| P1 | 时代上下文 + 9 槽位 + 4 张清装身份卡 + 三段提示词 + 覆盖变量 + 预算分档 | 4 张卡能稳定出「一眼可辨阶级」的图；check-prompt 通过 | 3–4 天 |
| P2 | 品级/场合扩展（文官 1–9、武官、命妇、朝/吉/常）+ 服饰拆解画幅 + 一致性 | 18–24 张卡；服饰拆解版面 | 1–2 周 |
| P3 | 明/唐/汉 + 日本江户/朝鲜/越南文化包 | 同一套 schema 复用 | 每包 3–5 天 |

**MVP 先做 4 张卡跑通，再扩到 8–12 张**（数据模型文档按 4 张算过账：男官 / 旗女 / 汉女 / 平民，服饰句 66–74 字/张）：

1. 旗籍文官（正二品）· 补服
2. 旗人贵妇 · 袍褂（盛清；氅衣/花盆底留到晚清卡）
3. 汉人士人妻 · 袄裙
4. 汉籍平民 · 短打

第二步再加：商人（绸袍马褂）、书生（长衫马褂）、农妇（短袄布裤）、衙役/仆役（短衣号衣）。皇帝/宗室放 P2：龙纹、明黄、东珠最容易翻车，也最敏感；先把「官—士—民」这条最常用的线跑通。

**验收不要用「像不像清朝」这种主观判断**，用 10 项锚点打分：补子位置/禽兽、顶珠、朝珠、马蹄袖、披领、开衩、发式、鞋、主色、场合。每张卡出 4 张图，≥7 项锚点正确才算通过。
