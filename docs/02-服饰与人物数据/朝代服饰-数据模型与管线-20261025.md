## 0. 结论先说（五个锁死的数字与决定）

1. **预算已经没有余量**：实测 `node scripts/check-prompt.mjs` 当前各画幅 2095 / 2097 / 1764 / 1761 / 1793 字，预算 2100 / 2100 / 1800 / 1800 / 1800 —— 横版只剩 **3~5 字**，竖版 36~39 字，九宫格 7 字。**清装要落地，必须先腾字数，再加服饰句**（§3.4）。
2. **`params.json` 加两组参数**（`context` 3 项 + `costume` 9 项），73 → **85 项**；选项 317 → **360 项**。`data/eras.json` 只放词表/负向/联动/考据，不放参数。
3. **门控是选项级字段 `g`**，与现有 `w`（分性别权重）AND 合取，只改 `weightOf()` 一个函数（`app.js:237-241`）就能让「允许可点 / 可随机 / 会被 clamp」三件事同时生效。
4. **`underTop` / `outfitExtra`（`app.js:441-444` 硬编码）必须改成 `coverageVars(sex, era)`**；`layout.vars` 里对 `outfitExtra` 的整句覆盖改成新变量 `frameCrop`，否则清装描述会被裁切句整句吃掉。**这两个坑不修，补服会和裸上身同现。**
5. **预算分档**：`budgetFor(orient, era)`，素体态维持 1800 / 2100；清装态理论上限 1900 / **2200**。但 §3.4 的账算下来：净增 +113 字、腾挪 −125 字后横版只到 **2083**，**2100 已经够**，抬到 2200 只是给 P2（全展开 + 补句）留的余量，不是现在就必然吃满。

## 1. 本体设计：era → culture → rank → occasion → slots

### 1.1 四层 + 一条硬约束

```
era（朝代：none / qing / ming / tang / song …）
 └─ culture（服饰文化归属：满 / 汉 / 蒙古 / 回 / 藏 …；清代内部再分「旗籍 / 汉籍」）
     └─ sex（复用现有三态，硬约束，不改）
         └─ rank（身份阶级：宗室 / 官员上 / 官员下 / 士人 / 商贾 / 平民 / 仆役 / 僧道 …）
             └─ occasion（场合：常服 / 吉服 / 朝服 / 行服 / 素服）
                 └─ slots（9 个服饰槽位：能穿什么由上面四层共同过滤）
```

**hard constraints（不能做成滑块）**：`sex`（现有 `params.json` identity.sex）+ `era`。两者都遵守现有约定：**硬约束优先于锁定**（`app.js:396-404 setSex` 的语义，README「切换性别时会发生什么」）。`era` 切换时 `state.locks` 只决定「换一个」是否重掷，**不阻止**跨时代非法值被自动修正。

### 1.2 三类属性：谁是角色、谁是服饰、谁只是约束

| 类 | 字段 | 落在哪 | 会不会改身体 | 改谁 |
| --- | --- | --- | --- | --- |
| **角色属性** | `era` `culture` `sex` `rank` `occasion` `age` | `params.json` 的 `context` 组（`sex`/`age` 仍在 `identity`） | 只有 `era` 通过 `eraLinks` 联动毛发/胡须/妆容 | 换时代/阶级 = 换整套可选集 |
| **服饰属性** | `headwear` `outer` `inner` `lower` `shoes` `accessory` `pattern` `material` `color` | `params.json` 的 `costume` 组（L7） | 否 | 只进服饰两段 |
| **提示词约束** | 时代负向词、色禁/纹样禁、结构可读性条款、画幅裁切句 | `data/eras.json`（词表）+ `templates.json`（结构与内容段） | 否 | 不进左栏，只进编译 |

判据：**能改变「长什么样」的进 params；只改变「怎么写」的进 eras.json / templates.json。**

### 2.3 门控字段 `g` 的判定语义（唯一改点）

```js
/* 选项级可选字段 g（AND 合取；键缺省 = 不约束）
   g = { era:["qing"], culture:["manchu","han"], socialClass:["official_high"], occasion:["ceremonial"] }
   性别不用 g —— 继续用现有 w（分性别权重），两套机制正交叠加 */
function gateOk(o, ctx) {
  const g = o && o.g;
  if (!g) return true;
  return Object.keys(g).every(function (k) {
    const allow = g[k];
    return !Array.isArray(allow) || allow.length === 0 || allow.indexOf(String(ctx[k])) >= 0;
  });
}
/* app.js:237-241 的 weightOf 原样保留，只加一行返回 0 —— 五个调用点自动生效：
   allowedOptions(242) / clampToSex(290) / renderChoice(1183) / openParamDetail(1317) / pickWeighted(258) */
function weightOf(o, sex) {
  if (!o) return 1;
  if (!gateOk(o, state.params)) return 0;        // ← 新增行
  if (!o.w) return 1;
  const v = o.w[sex];
  return typeof v === "number" ? v : 1;
}
```

由此**「性别硬约束」与「时代/阶级门控」天然合并**：`weightOf > 0` 就是「可用」的唯一定义，界面置灰（`renderChoice:1183-1190`）、随机候选（`pickWeighted:258`）、clamp 修正（`clampToSex:279-298`）三处行为不再分叉。

与现有 `conflictRules`（`params.json` 顶层，`validate-data:188-205` 校验，`collectHealthIssues:1396-1402` 执行）**正交**：`g` 管「能不能选」，`conflictRules` 管「选了会不会打架」。服饰层的「阶级↔形制」「场合↔冠服」冲突用同一结构写在 `eras.json.rules`，执行时两个数组拼起来即可：

### 2.5 为什么不会组合爆炸：三层拆解 + 数量级

```
朴素做法（每语境一段文案）：4 朝代 × 2 文化 × 3 性别 × 10 阶级 × 3 场合 = 720 语境
                          × 9 槽 = 6,480 条文案 × 平均 3 变体 ≈ 19,440 条 ≈ 6~8 MB，无法维护。

本设计三层：
  ① 条件选项：43 个选项 × 4 朝代 = 172 条（每条 1 行 phrase + 1 行 desc + g）≈ 60 KB
  ② 槽位：9 个槽位定义（order/required/分组/连接词/负向）≈ 3 KB
  ③ 预设：4 朝代 × 10 阶级 = 40 张卡（每张 9~12 个 values）≈ 40 KB
```

### 3.3 槽位拼句算法

```js
/* eras.json 的 slots 每项带 part/order/lead，决定它进「形制」还是「料色」、带什么动词前缀 */
function costumeSentence() {
  const E = DATA.eras, era = state.params.era;
  if (era === "none" || !E) return "";
  const meta = E.eras.find(function (x) { return x.id === era; });
  const head = "服饰形制：" + meta.label + (classLabel() ? classLabel() : "") + "，";
  const parts = [];
  E.slots.filter(function (s) { return s.part === "wear"; }).forEach(function (s) {
    const v = state.params[s.id];
    const p = paramIndex[s.id];
    const o = p && p.options.find(function (x) { return x.value === v; });
    if (!o || o.value === "none" || !o.phrase) return;      // 空槽直接跳过，不留逗号
    parts.push((s.lead || "") + o.phrase);
  });
  return parts.length ? head + parts.join("，") + "。" : "";
}

function costumeNegSentence()  { /* era 全量负向 + rank 专属负向，join("；")；era=none 返回 "" */ }
```

**拼句规则**：① 空槽跳过、不补标点；② 必需槽为空视为数据错误（校验拦截），运行时兜底用 `slots[].fallback`；③ 每槽 `phrase` **不带首尾标点**（逗号由 join 提供），旧 `outfitExtra` 那种自带「，」的写法只保留在 `frameCrop` 里；④ 单槽 phrase ≤ 18 字，`costume` 段 ≤ 56 字，`costumeMake` ≤ 28 字，`costumeNeg` ≤ 52 字（§6 B2 断言）。

### 3.7 复合变量的「单一出口」与四处连带账（回应左栏方案 §4.7）

三段正文只有一个复合变量（`{{costume}}` 等），9 个槽位参数**不出现在任何段文本里**。按现有实现会同时炸四处，且都不是提示词问题、是界面在说假话：

| 位置 | 现象 | 修法 |
| --- | --- | --- |

**单一出口怎么定**：不放 validate、也不各端各存一份，而是**放进数据**——内容段定义里加可选字段 `covers`：

**统一形状：返回原因，而不是返回布尔**（左栏方案 §4.7 P5）。布尔只能回答"用不用"，回答不了"为什么不用"，于是角标与编译真值必然各写一套、迟早走岔：

```js

function blockInactive(b) {
  if (isBlockSuppressed(b.id)) return "layout";          // 本画幅的版面停用（现有机制）
  const c = DATA.content[b.id];
  const when = c && c.when;
  if (when && Object.keys(when).some(function (k) {
        return when[k].indexOf(String(state.params[k])) < 0;
      })) return "era";                                  // 本时代未启用（新增）
  return null;
}
```

## 8. 风险清单

| # | 风险 | 触发点 | 缓解 | 监控 |
| --- | --- | --- | --- | --- |
| 1 | **模型审美偏影视化**（清宫剧/影楼亮片/浓妆） | 服饰句只给物件，模型按训练集补「戏服」 | 把可判定的**结构锚点**（开衩高度、补子位置、马蹄袖翻折）写进 `structure.layout` 而非形容词；负向集中一处便于迭代；每批抽检 10 张记通过率 | 通过率 <70% 进下一轮负向词 |
| 2 | **提示词长度**（现在只剩 3~5 字余量） | 三新段 + 腾挪不当 | §3.4 配额表 + 逐段断言 + 分档预算 + 降级顺序 | `npm run check` 段超配额即拦 |
| 3 | **数据维护成本**（4 朝代 × 10 阶级 = 40 卡） | 每个新朝代都要重写 9 槽文案 | 三层结构 + `presets[].extends`（继承父卡只写差异）+ 脚本生成骨架；P1 只做 4 卡 | 新增一张卡 ≤ 40 行 JSON |
| 4 | **考据错误责任** | 品级/补子/花翎等制度细节写错 | 每卡 `confidence` + `sourceRefs` 强制非空（validate 断言）；UI 标「考据存疑」；README 声明「创作辅助，非学术复原」；用 `stylisticAnchor` 收敛年代口径 | 低置信卡在参数详情标红；存档可回溯 |
| 5 | **审核与敏感内容** | 民族议题（剃发易服）、阶级侮辱场景、露肤 | 文案中性、只写制度与形制不写压迫叙事；负向禁「敞怀/露胸」；素体条款被服饰句替换时不得降为低领；不写政治符号与侮辱性情境 | 上游审核错误按模型分组汇总 |
| 6 | **性能** | 左栏 +12 参数、`eras.json` 变大、门控遍历 | `costume` 组带 `ctx` 只在 era≠none 渲染（人模式只多 1 行摘要，见左栏方案 §4.6）；`weightOf` 一次 `indexOf`；A1 的 720 组合是毫秒级 | 首屏渲染 < 50ms；`eras.json` gzip 后 ≤ 30KB |
| 7 | **门控覆盖漏洞**（某 rank×sex 无可用槽位） | 数据手写遗漏 | A1 断言 + `slots[].fallback` 逐级回退（阶级→父阶级→通用） | 断言即拦，不进运行时 |
| 8 | **与左栏改造撞车** | 两条线并改 `renderParams` / `index.html` / `style.css` | P0 先落信息架构，P1 只加「服饰组渲染 + 4 张卡」，不改左栏骨架；写权限按文件切分 | 合并前 `npm test` + 左栏 §5.5 的 scrollHeight 口径 |
