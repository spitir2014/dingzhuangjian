# 左栏信息架构改造方案

> 项目：造像台 · 人物设定稿
> 日期：2026-10-25　范围：`web/index.html` / `web/style.css` / `web/app.js` / `data/params.json` 的左栏部分
> 结论对象：7 个分组、73 项参数、317 个选项、284px 栏宽
> 纪律：本文只做诊断与方案，**不含代码改动**；所有高度/节点数值来自 CSS 盒模型推算 + `data/params.json` 逐项统计，测量口径见 §1.1 与附录 A。
> **修订（2026-10-25）**：§4.5 / §4.7 已按 `docs/02-服饰与人物数据/朝代服饰-数据模型与管线-20261025.md` 的实测数据对齐 —— 预算不再新增 2,600 档（实跑 2,095/2,100，净增 +113、腾挪 −125 → 2,083）、新增 `costumeNeg` 负向段、门控改用选项级 `g`、补 6 个「不改就露馅」的界面侧改动。§0–§3 与 §5.5 的量化结论未受影响。

## 0. 一句话结论

左栏不是「参数太多」，而是**每一层都同时展开、且没有任何一层可折叠**：73 项 ×（参数名 + 变量名 + 3 个工具按钮 + 全部选项 + 词句行）全部常驻。推算整栏滚动内容 **7,399px ≈ 11.6 屏**，1440×900 下首屏只看得完 **4 项参数（5.5%）**，而改一项的平均代价是「先滚 5.8 屏再点 1 下」。

改造主线：**把「查看」和「编辑」拆成两层（摘要行 → 展开体 + 值浮层），并把「时代/身份」作为上下文条提前占位**；其余能力（☆ / 掷 / 锁 / 未用 / 定位 / 词典 / 体检 / 折叠 / 搜索 / 预设 / 快捷键）全部原样迁移。

### 五个必须记住的数字

| # | 指标 | 现状 | 目标 |
| --- | --- | --- | --- |
| 1 | 左栏滚动内容高度 | **7,399px**（11.6 屏） | ≤ 2,900px（≈4.5 屏） |
| 2 | 首屏完整可见参数 | **4 / 73（5.5%）** | ≥ 12 / 73 |
| 3 | 词句行占整栏高度 | **1,656px（22.4%）** | 0（默认并入摘要行） |
| 4 | 整栏 DOM 节点 / 常驻按钮 | **≈2,100 / 536** | ≤ 1,200 / ≤ 120 |
| 5 | 到达任意参数的平均滚动 | **5.8 屏** | ≤ 1 屏（其余走搜索 / 定位） |

单行结构（`renderParams`，`app.js:1085-1177`）：

| --- | --- | --- | --- | --- |

| 数值型 | 14 | 7 | **21** | 3 |

整栏合计：

| 指标 | 数值 |
| --- | --- |
| 元素节点 | 1,186 |
| 文本节点 | 818 |

| 按钮 | **536**（317 个选项 + 219 个工具按钮） |

| 视觉单元（可辨识的"块"） | **834**：317 按钮 + 219 工具 + 73 变量名 + 73 名称 + 73 词句 + 72 虚线 + 7 组头 |
| Tab 穿越整栏 | **536 次** |

重渲染路径：`renderParams()` 会 `host.textContent = ""` 整栏重建，它被以下位置调用：

| 触发点 | 代码位置 | 是否必要 |
| --- | --- | --- |
| 点「锁」 | `app.js:1148` | 只需改 1 行 class |
| 点「☆」 | `app.js:1241`（`toggleHighlight`） | 只需改 1 行 class |
| 点分组头 | `app.js:1039`（`toggleGroup`） | CSS 切换即可 |
| 搜索框每输入 1 个字符 | `app.js:3344-3347` | **每次击键整栏重建 2,100 节点** |
| 点任意选项 | `app.js:1196` → `syncAll`(2127) → `renderParams` | 只需改 1 行 |
| 点滑杆（input 事件） | `app.js:1212-1222` | 不重建，但 `updatePromptPreview` → `updateParamUsage`(750) 会 `querySelectorAll('#paramGroups .param')` 遍历 73 行、每行再查 `.param-use` = 146 次查询 / 事件 |
| 切换画幅 / 详细度 | `app.js:3559` / `app.js:1273` | 可接受 |

**关键结论：折叠分组并不会降低 DOM 成本**——`.group.collapsed .group-body{display:none}`（`style.css:798`）只是隐藏，73 行永远在 DOM 里、永远参与 `querySelectorAll`。

### 1.6 改一个参数要付多少代价

| 路径 | 操作序列 | 点击数 | 滚动 / 键入 | 覆盖率 |
| --- | --- | --- | --- | --- |
| 首屏行内直选（当前最短） | 点选项按钮 | **1** | 0 | 4/73 = **5.5%** |
| 行内直选（平均） | 滚到目标 → 点选项 | 1 | **≈37 格滚轮 / 5.8 屏** | 94.5% |
| 搜索 | 点搜索框 → 输 1–2 字 → 点选项 | **2** | 2–4 键 | 100% |
| 词典 | 点「词典」→ 搜索 → 点行 → 跳左栏 → 点选项 | **4** | 2–4 键 | 100% |
| 详情（查说明再改） | 点参数名 → 读 → 关闭 → 点选项 | **3** | 0 | 100%，但**弹窗不能设值** |
| 掷单项 | 点「掷」 | 1 | 0 | 只给随机值 |
| 确认词句 | 点词句行 → 跳右栏高亮 | 1 | 右栏再滚 | — |

两点必须点名：

1. **「参数详情」弹窗是只读的。** `openParamDetail`（`app.js:1293-1333`）里的选项行是 `<div class="pd-row">`，没有任何点击处理器，弹窗底部只有「掷一次 / 设为记忆点 / 关闭」。也就是说：**「我想看看这个选项是什么意思，再选它」这条最自然的操作，现在要走 3 次点击 + 2 次弹窗开关**，而其中一次点击必然是无功的关闭。
2. **搜索单字平均命中 14 项。** 按 `paramMatches`（`app.js:1019-1024`）的匹配字段（id / label / note / impact / 词句 / 选项 label / desc / phrase）实测：搜「眼」18 项、「发」24 项、「色」21 项、「眉」10 项、「唇」11 项、「白」7 项、「手」6 项、「高」13 项，**单字平均 13.75 项**。14 项 × 97px ≈ 1,360px ≈ 2.1 屏——搜索并没有把「5.8 屏」变成「0 屏」，只是变成「2.1 屏」。

### 1.7 两套导航的重叠与冲突

左栏同时存在 **4 套**"改变可见内容"的机制，但它们语义不互补：

| # | 机制 | 控件 | 改的是 | 问题 |
| --- | --- | --- | --- | --- |
| 1 | 搜索 | `#paramSearch` | 过滤参数 | 命中后**不滚动到第一个命中、不高亮匹配片段、不按相关度排序**；结果项仍是全展开 |
| 2 | 层级筛选 | `#paramFilters`（全部 / 核心 / 进阶 / 未用） | 过滤参数 | 先按 tier 再按 query（`paramPassesFilter`，1026-1032）；核心视图下搜进阶项 = 空结果，且提示是"没有匹配"，不说"被筛选掉了" |
| 3 | 分组折叠 | 组头 chevron | 隐藏组体（CSS `display:none`） | **搜索命中在折叠组里时，用户看到的是"没有结果"**：组头还在、行被隐藏、`visible` 计数非 0，所以连空态提示都不出现 |
| 4 | 工具栏「词句」 | `#togglePhrases` | 全局密度（±23%） | **它本来就是唯一有效的密度旋钮，却被当成"参考信息开关"**，默认常开 |

由此派生 3 个**功能性缺陷**（不是审美问题）：

- **折叠 + 定位静默失败**：从右栏点变量走 `locateSource`（`app.js:705-728`）→ `document.querySelector('#paramGroups .param[data-id=...]')`。行还在 DOM 里（只是 `display:none`），`scrollIntoView` 对隐藏元素无效 → **什么都不发生、也没有提示**。（`locateParam`（1278）会展开分组，`locateSource` 不会——两套定位逻辑。）
- **筛选 + 定位静默失败**：`tierFilter="core"` 或搜索态下，目标行根本没被渲染，`querySelector` 返回 null → 静默失败。
- **「未用」在默认档下为 0 条，切「简洁 / 标准」时一次冒出 18 条**：`DETAIL_PRESETS`（`app.js:1252-1256`）关闭 `detailFace`(10 项) + `detailBody`(8 项) 两个内容段 → 这 18 项同时变成「未用」，18 行 × 右侧"未用"二字 + 整行变灰，噪音集中在最不该加噪音的时刻。

### 1.8 小结：密集感的五个可测来源

| 来源 | 量化 |
| --- | --- |
| 选项全量铺开 | 317 个按钮 / 86 行 / 2,448px（35%） |
| 行头三件套常驻 | 219 个工具按钮（42% 不透明度）+ 73 个 8.5px 变量名（平均 59.2px，占行宽 **23%**） |
| 词句行默认常开 | 1,656px（24%），是"每一行都有第二行字"的观感来源 |
| 无层级 | 73 项全在同一深度；26 项的面目一列到底（2,510px = 4 屏） |
| 低对比小字 | 8.5–10px × 每行 3–4 处；`--ink-4 #A9AAA3` 在 `#F6F6F3` 上 = **2.16:1**、`--ink-3 #85867F` = **3.39:1**，均低于 WCAG AA 的 4.5:1 → 大片"灰噪音" |

## 2. 问题归因（按影响排序）

| # | 归因 | 影响 | 证据 |
| --- | --- | --- | --- |
| 1 | **没有「查看 / 编辑」分层**：选项按钮、说明、词句、变量名全在同一层，且"看说明"要开除只读弹窗 | 最大。一次"看→改"要 3 次点击、2 次弹窗开关 | `openParamDetail` 的 `.pd-row` 无点击处理器（1293-1333） |
| 2 | **选项全量铺开**：68 个选项型参数把所有候选值都渲染成按钮 | 2,448px + 317 个边框 = 单栏 834 个视觉单元 | §1.2 选项占行 86 行；平均每行只放 3.65 个 |
| 3 | **每行 3 个工具按钮常驻**（☆ / 掷 / 锁，opacity .42 常显而非 hover 显） | 219 个按钮 + 每行 3 个 tab 停靠点，视觉与键盘双负担 | `style.css:167-168`（`.param-tools{opacity:.42}`） |
| 4 | **词句行默认开**，且是独立一行 | 1,656px（24%），每行都变成"两行字" | `state.showPhrases` 默认 true（`app.js:54`、`148`）；`style.css:601` |

| 6 | **进阶 42 项与核心 31 项混在同一视图**，`tierFilter` 默认 `"all"` | 57% 的项是"偶尔才调"的，却和常用项同权重 | `app.js:49`；工具栏已有 chip 但默认全部 |
| 7 | **变量名 8.5px 常驻**，占 23% 行宽 | 73 个等宽 token，是"工程感"和"密"的主要来源，但只在调试映射时才需要 | `style.css:585-588`；`renderParams:1125` |

## 3. 三套方案

三套方案共享一个**前提改造（P0）**，先讲清楚，否则 A 会牺牲现有的"1 次点击改值"。

### 3.0 共同前提 P0：摘要行的两种点击语义

摘要行不是"折叠起来的一行死文字"，它有两个热区：

| 热区 | 行为 | 成本 |
| --- | --- | --- |

### 推荐：**A 为主，吸收 B 的检查器形态（0.5 天），预留 C 的上下文条（0.5 天）**

理由，逐条对着项目约束：

1. **单人本地工具，改动成本必须小于收益。** A 用 1.5–2 人日拿到 −63% 高度和 3 倍首屏；B 要 3–4 天，换来的部分收益（+4 行、检查器）A 用 0.5 天的「详情弹窗可编辑」就能拿到 90%。
2. **键盘快捷键已存在，A 的键盘化路径最短。** `[` / `]`（`app.js:3776-3782`）、`Esc`（`3490-3502`）已有统一入口，新增 `/`（搜索）、`j/k`、`Enter`、`1–9` 只是加分支；B 的"选中态"需要额外焦点模型，C 需要模式切换的键位分配。
3. **1440×900 一屏要同时看见画布。** 中栏现在只有 **756px 宽（52.5%）**：左栏 284 占 19.7%、右栏 352 占 24.4%，两栏合计 44.2%。A 与 C 都不动栏宽；B 的底部检查器继续吃左栏垂直空间——而左栏是三者中最缺空间的。真正能放大画布的是**摘要化之后允许左栏收窄到 248–260px**（A 之后才成立）。
4. **B 的核心价值不是布局而是「一处编辑、旁边有说明」，把它搬进现有弹窗即可。** `openParamDetail` 已经渲染了 note / impact / 选项 desc / 三性别可用性 / 用在哪些段，**只差把 `.pd-row` 变成可点击**。这一步 0.5 天，消掉"查说明再改"的 2 次点击，比上 B 便宜 6 倍。
5. **C 现在做会做出两个空模式。** 清装数据（9 槽位选项、身份卡、提示词两段）还没有，先做 C 只能得到 3 个 tab + 1 个空壳。正确顺序：**A 把现状压下去 → 清装数据定稿 → 再把 C 的上下文条接上**（第 4 节给的就是这个接口）。

因此第 5 节落地清单 = **A 的全部 + 弹窗可编辑 + 上下文条占位**，C 的完整形态放进「以后」。

### 4.5 提示词落点（已按 task-3 实测修正）

1. **`templates.json` 的 `outfit` 段只有 31 字**（原文「服装：{{underTop}}{{outfitExtra}}。」）。清装要写 9 槽，**必须新增三段**而不是塞进 outfit（与 task-3 §3.2 一致；每段正文只放一个**计算变量**，句子在 JS 里拼）：
   - `costume` → `{{costume}}`（服饰形制，≤56 字）
   - `costumeMake` → `{{costumeMake}}`（纹样与质色，≤28 字）
   - `costumeNeg` → `{{costumeNeg}}`（服饰负向，≤52 字）
   - 三段都要进 `DETAIL_PRESETS`（清装态强制开）。`era="none"` 时三个变量返回空串 → `compilePrompt` 的 `.filter(text => text.trim().length > 0)`（`app.js:504`）自动丢段，**素体态零预算影响**。**但这条 trim 过滤只对「没被手改过」的段有效**：段文字可编辑并持久化（`persistBlocks` 1694-1698），一旦在清装态手改过，切回素体时它是非空的 → 必须在编译层用 `when` 硬过滤（§4.7 P5）；右栏同样会多 3 个空段。

2. **`data/layouts.json` 已经用 `vars.outfitExtra` 做版面改写**（`portrait` / `expression_grid` 都覆盖它）。清装若往 `outfitExtra` 塞服饰描述，会被版面改写**整句覆盖**。两种解法：

   拆变量是加法：`layouts.json` 5 个画幅各加一行 `frameCrop` 即可（素体态为空串），`scripts/check-prompt.mjs` 的断言跟着加。
3. **预算：不是「加预算」，是「先腾挪再花」**。`node scripts/check-prompt.mjs` 实跑（2026-10-25）当前五画幅 **2,095 / 2,097 / 1,764 / 1,761 / 1,793** 字，横版预算 2,100 **只剩 5 字**。task-3 §3.4 的账：净增 +113（三段）、腾挪 −125 → 横版 **2,083 ≤ 2,100**。
   - 因此 `budgetFor(templateOrient(), state.era)` 保留，但清装档 **2,200 只作上限缓冲、不作目标值**（本文早先写的 2,600 是「9 槽约 +180–260 字」的粗估，实测只有 +113，该数字作废）。
   - 超预算的降级顺序写进 `#promptMeta` 的 `title`（`app.js:2104` 现在只写静态说明）：关 `costumeNeg`（−51）→ 关 `costumeMake`（−28）→ 切「标准 / 简洁」（−239）。仍走现有 `.budget-warn` / `.budget-over`（`style.css:808-811`）。

- **措辞抽纯函数，能先于清装数据跑回归**：把停用状态的中文与 class 抽成 `blockStateText(b) → {text, cls}`（不碰 DOM），`renderBlocks` / `renderBlockMeta` / `offHint` 只做取值与挂载。这样 `test-layouts` 可以加一条 C3：九宫格 `info` 段满足 `blockStateText().text` 为「本画幅不用」且 `blockInactive()` 为 `"layout"` —— **在清装数据落地之前**就把上面那个既有矛盾锁成回归，是这 6 点里唯一能先跑起来的断言。

- **`covers` / `when` 只写在 `data/templates.json` 的 `content[id]` 上**：`defaultBlocks()`（1584）与 `ensureBlockSkeleton()`（1629-1636）构造 block 对象时只取 `{id, kind, label, text, enabled}`，不带这两个字段也没关系 —— 各处用**段 id** 去 `DATA.content[id]` 取即可（`loadData:101` 已经把整个 `content` 原样挂到 `DATA.content`）。这样不必动 `state.blocks` 的结构，localStorage 里的旧 blocks 也不用迁移。

另外两条接线约定：

- **变量名与参数 id 不许撞名**：`paramIndex` 里若出现 `costume` / `frameCrop` 这样的参数 id，`varMetaFor` 会先命中参数、把复合变量当成普通参数（变量表来源指错）。组 id 用 `costume` 无害（组不在 `paramIndex` 里），但**参数 id 不要用这四个名字**。
- **扩一条版面改写提示**：`openParamDetail` 的「本画幅被版面改写」判定（app.js:1309）要加上 `frameCrop` —— 非空时在「着装」段旁标注「本画幅裁切由版面接管」，否则用户看到服饰描述变短会以为丢了。
