# 造像台 · 三方一致性修复说明（2026-10-25）

> 本轮把「参数 → 变量 → 提示词 → 发送」收敛为一条管线，修左栏 / 右栏 / 预览 / 批次之间的口径不一致。
> 只记录改动与取舍；史实核验与真实出图结论仍在 [P2 实施说明](P2实施说明-20261025.md) 与 [P2 真实出图验收](P2真实出图验收-20261025.md)。

## 背景

造像台由三份数据共同决定一张图：左栏 87 项人物参数、`data/eras.json` 的 36 张身份卡与 9 个服饰槽位、右栏提示词编排（结构 4 段 + 内容 16 段 + 自定义段）。三份数据各自演化后出现同一类问题——**同一个事实有多套口径**：

- 预览和实际发送各拼一遍提示词，空值、未知变量在两边表现不同；
- 「换一个」只换人，却被身份卡、锁、派生、相关性按不同顺序反复改写，结果不可解释；
- 身份词取卡片形制名（「文官正一品·补服」），被写进左上角文字；
- 身份卡失效后槽位不清理，素体态残留上一个时代的「暖帽」「补服」。

本轮不新增参数，只把口径统一，并把坏数据挡在提交前。

## 设计决策

### 1. 优先级：硬约束 > 锁定 > 派生 > 相关性 > 随机

所有改值入口（改选项、单项掷、换一个、换卡、切性别、切时代）只走 `commitParams`，内部顺序固定：

```
上下文 → 硬约束（性别 / 门控）→ 身份卡 → 相关性 → 派生 → 清理
```

- **硬约束**永远赢：女性不出现男性胡型，门控不满足的选项不可选。
- **锁定**只对「换一个」生效，但拦不住硬约束。
- **派生**是确定性联动（剃发 → 寸头 / 无刘海 / 无分缝；长发 → 发长至少到胸）。
- **相关性**是概率项，只调未锁、未被卡固定的项。
- **随机**填剩余项。

被更高优先级拦下的调整不静默吞掉：联动冲突进「体检 → 参数冲突」，被卡压住的锁进「体检 → 身份卡与解锁」。

### 2. 单一快照：预览就是发送

`buildPromptSnapshot()` 是唯一拼提示词的地方，返回正文、段列表、字数、`used / empty / unknown`。预览面板、复制按钮、生成请求、存档 `prompt` 全部读这一份；`compilePrompt()` 只是 `snapshot.text` 的别名。任何「预览一套、发送一套」的路径都去掉。

### 3. 空值：不写进正文

变量没有词句时编译成空串。用 `mode: "exact"` 渲染，不出现「（空）」占位符；一段因此为空则整段不输出。变量 chips 仍标「空」并在悬停里说明「不会输出文字」，方便定位而不污染正文。

### 4. 未知变量：先剥掉、再拦截

编译段落时只替换快照里存在的键，其余直接移除。生成前若快照 `unknown` 非空，拦下请求并打开体检；复制时提示已移除的数量。这样错误变量名不会变成画面里的文字，也不会静默发出去。

### 5. 身份与卡片名分离

- `identity` 是名词短语，由 `era + role + rank + community + sex` 推导（`identityPhrase()`），只用于「左上角文字」那一行。
- 卡片名（文官正一品·补褂、晚清旗人贵妇·氅衣）只用于卡片 UI、证据与存档；不写进提示词，避免「·」被模型当成画面文字。
- 卡片换性别时整套档案重生成，身份词跟着卡走。

### 6. 身份卡覆盖优先，但可被手改

- 卡有效时 `applyIdentityCard()` 把 overrides 压回参数；用户手动掷/改过的项记入 `lookCustomized`，不再被压。
- 锁挡不住卡：卡覆盖优先于锁。参数名旁出现「卡」= 该参数由身份卡固定（悬停显示「由身份卡『卡名』固定」）；若同时又上锁，锁的提示改为「身份卡优先：换一个/换卡时会按卡片改它」，体检「身份卡与解锁」给出一键解锁。
- 换卡 / 换时代 / 切性别会清 `lookCustomized`，重新受新卡约束。

### 7. 槽位不参与随机、不提供锁

- 9 个槽位由身份卡与门控决定，「换一个」跳过服饰组；槽位不在掷的范围内，所以也不提供锁。
- 时代=素体：9 个槽位清空，槽位变量输出空串。
- 时代开着但槽位全空：服饰句仍输出身份行，不产生「服装：。」。
- 手改出非法值时静默置空（回「无」），不会重掷成另一个值；门控不满足的选项在界面上置灰。

### 8. 派生是确定性规则，不是随机倾向

发型 → 发长 / 刘海 / 分缝、体型 → 身形、头身比 → 腿身比、年龄 → 面部纹路等写进 `applyDerived()`，可预测、可解释；被锁或卡挡下时记录到 `derivedConflicts` 并进体检。手动掷 / 改过的派生项由 `manualOverrides` 保护，当次派生不再覆盖它；下一次「换一个」或换卡会清空这层保护，重新按硬约束与派生对齐。

### 9. 批次先拍快照

点「生成」时先按张数静默重掷并逐张拍快照，再统一发请求；并发生成期间页面不再重绘左侧参数，后一张不会改掉前一张的 prompt。重试沿用原快照。

### 10. 掷与种子分工

- 单项「掷」：不推进种子，按「种子 + 参数 + 第几次掷」取随机，点到变为止（最多重试），不可用种子复现。
- 「换一个」：换新种子并重掷未锁项。
- 种子行「应用」：用输入种子重建；复现条件 = 种子 + 锁 + 时代 + 身份卡都相同。

## 已知取舍

- **掷不可复现**：单项掷不推进种子，换来的是「点一次一定换值」；要复现请用种子行「应用」。这是有意取舍：两种随机入口各自负责「变」和「复现」，不混在一起。
- **未知变量直接拦截**：旧存档里手写的错变量会导致无法直接生成，需要先改成正确变量或删掉；这是为了避免把 `{{…}}` 发给模型。
- **换时代 / 切性别会清槽位并与卡脱钩**：宁可让用户重新选卡，也不保留上一时代或异性别的服饰残留。
- **身份词只从 role / rank / community 推导**：没有专用身份卡的组合会退到通用词（如「兵丁」「农户」）；本轮不改 role 选项体系。
- **卡名去重只改显示名**：`qe_official_civil_1` 的 id 未变，旧存档与旧测试不受影响；README 的十卡列表同步改为「补褂」。
- **校验只覆盖静态数据自洽**：`validate-data.mjs` 不替代 `test-model.mjs` 的行为断言；两处都过才算通过。
- **相关性仍是概率项**：「换一个」后仍可能掷出少见组合，由体检提示，不在这次改动里强行收敛。
