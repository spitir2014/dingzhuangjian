- 拆解画幅停用人物文字段，只保留无文字细节窗和色块；素体时点击生成会提示先选时代，不发付费请求。

## 存档与接口兼容

继续使用现有 `/api/generate-batch`、`/api/layouts` 和存档接口，批次仍最多10张，模型并发上限未改变。

- `promptMeta.evidence` 增加卡ID、来源等级、类别、来源编号/标题/链接快照、限制、是否手改及品级推导快照。
- `character.lookId` 与浏览器状态保存卡ID，刷新后恢复；素体不携带上一张清装卡的证据。
- 新服务产生的存档沿用schemaVersion=4，补充 `imageDimensions`、`requestedSize`、`actualSize`、`sizeMatchesRequest`，从PNG/JPEG/WebP编码读取真实像素，不把上游回显当作实际尺寸。
- 画幅管理保存 `requiresEra` 标志，避免改名保存后丢失拆解画幅前置条件。旧存档和旧浏览器手改段仍可读。

## 使用与复验

时代选择在左栏“身份”；身份卡与类别筛选在“服饰”。选择“服饰拆解与色卡”后，点生成仍使用原有付费流程。

```powershell
npm test
npm run test:batch
python scripts/test-p2-browser.py
npm run p2:live:plan
```

最后一条只读现有样本，不提交上游、不覆盖报告。当前已存在30张，显式执行也不会再发这30张；检测到未达真实2K的探针时，禁止继续缺失样本。不得为视觉低分盲重发。

常规启动仍使用 `启动.bat` / `node server.mjs --open`。现有8787进程缓存的是旧画幅；磁盘数据已修复，但需退出原启动窗口再启动才能加载新服务端。自动审批拒绝了停止该既有进程的命令，因此本轮保留原进程，通过独立端口与隔离测试验收新版。
