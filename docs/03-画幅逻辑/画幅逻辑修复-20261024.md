# 画幅逻辑审查与修复（2026-10-24）

> 范围：`data/templates.json`、`data/layouts.json` 里 5 个画幅的结构段，以及 `web/app.js` 的提示词拼装、`server.mjs` 的 `/api/layouts` 持久化、`scripts/validate-data.mjs` / `scripts/check-prompt.mjs` 的校验。
> 详细逐条审查报告见 `docs/03-画幅逻辑/画幅逻辑审查-其余画幅.md`（四个画幅）与 `docs/03-画幅逻辑/画幅逻辑审查-管线与数据.md`（管线）。

## 一、「表情九宫格」：表情重复 + 像俯拍的根因

### 1. 表情重复

- **根因**：整份提示词里只有一个表情变量。`data/templates.json` 的 `content.expression` 是「表情：{{expression}}。{{intensity}}。{{gaze}}。」，全画幅共用一份；版面段原来只写了「九格…只有表情不同」，**从没告诉模型哪九种表情**。
- **为什么模型只能复制**：提示词里没有任何「九格依次是 A/B/C…」的信息，模型只能把唯一那个表情画九遍，或者随机漂移。存档里五张九宫格分别用的是 laugh / cold / fear / smirk / angry —— 每张都只随机到一个表情。
- **修法**：版面段里给出**按格排列的九条表情清单**（平静→微笑→轻笑→大笑→惊讶→害羞→生气→委屈→认真），并写「九格表情必须互不相同、一眼可辨，禁止两格重复」；同时用画幅级 `vars` 把共用的「表情」段改写成「按版面九格清单逐格执行，禁止重复」，避免后段的单一表情把九格重新压成一张脸。

### 2. 像俯拍 / 没有正对镜头

- **根因 A（最直接）**：全项目**没有任何机位/俯仰描述**。`grep "俯拍|仰拍|平视|机位|视平线"` 在整个项目里 0 处命中（修复前）。
- **根因 B**：存档记录里 5 张九宫格有 **4 张 `gaze = "down"`**（「视线向下，眼睑半垂」），参数本身就在让九格都低头。
- **根因 C**：构图信息（版面段）在提示词第 2 段，但「表情/视线」在第 15 段；单一表情 + 垂眼指令在长提示词后段仍然生效。
- **修法**：版面段新增机位句——「九格共用一个平视人像机位：相机与人物眼睛等高，镜头光轴水平，面部正对镜头，双眼看向镜头；不俯拍、不仰拍、不歪头、不转头」；九格表情全部写「看向镜头」；负面对应写「不要俯拍、仰拍、歪头、转头、侧脸，不要从头顶往下看」。并把 `params.json` 里「看镜头」的词句从含糊的「视线直视前方」改成「双眼看向镜头，视线与镜头持平」。

### 3. 九宫格顺带修掉的其它逻辑冲突

| 冲突 | 原状 | 处理 |
| --- | --- | --- |
| 文字压第一格脸 | 左上角文字段写死在画面宽 22% / 高 10%，正好落在第 1 格 | 画幅 `suppress: ["info"]`，九宫格不画文字，负面写「不要任何文字、字幕、编号」 |
| 9 格拉全身 | 着装段写「下身只穿短裤、身体轮廓清楚可见」 | `vars.outfitExtra` 改成「只到肩部，不出现躯干、下身与脚」 |
| 九格没有统一取景 | 原文只写「只拍到头部与肩部」 | 写死「头顶到锁骨、脸部居中、约占每格高度 2/3，九格大小/位置/朝向相同」 |
| 格线 vs 无边框 | 画幅段说「没有边框」，版面段又要「极细浅灰线」 | 画幅段改「没有外框、没有装饰边框」，版面段保留格内细线 |
| 左右对称 | 质感段统一写「左右对称」 | 删掉；表情/挑眉/冷笑/四分之三脸本来就不对称 |
| 负面提脚部 | 九宫格负面写「不要裁切掉脚部」 | 改成「不要裁切头顶或肩膀；不要画全身、腿、手」 |

## 三、新增/改动的机制

1. **画幅级 `vars`**：画幅对象可覆盖共用内容段的取值。九宫格用它改写 expression/intensity/gaze/outfitExtra，正背卡与三视图用它改写 gaze（背面像不回头），半身肖像改写 outfitExtra。左栏参数仍然作用于其它画幅。
2. **画幅级 `suppress`**：本画幅不参与拼装的段落 id（九宫格停用「左上角文字」）。提示词预览、参数用量、块列表都会遵守；块上显示「本画幅不用」，开关点不动。
3. **画幅级 `orient`**：`landscape` / `portrait` / `square` / `any`。顶栏比例禁用不兼容项，切画幅时自动修正比例。
4. **老存档迁移**：这一版整体重写了结构段文案。以前只要动过任何一个提示词块，`persistBlocks()` 就会把 4 个结构段全量抄进 `localStorage.templateText`，旧文案会盖住新默认。现在 `LEGACY_STRUCT` / `LEGACY_CONTENT` 注册旧默认原文，启动时只在「缓存文本与旧默认一字不差」时摘掉缓存文本（保留开关状态），用户真正手改过的内容不动。
5. **预算分档**：单图画幅 1800 字；正背卡 / 三视图 2100 字（多视图要写清三处分格的位置与机位）。`npm run check` 与右下角预算提示都按画幅分档。

## 八、已知取舍与后续建议

- **templates.json 与 layouts.json 仍是两份数据**：现在两处同步且都校验，但改文案必须两边一起改（本轮用脚本同改）。建议后续让 `layouts.json` 只存用户 diff，或让服务端在缺字段时回落 templates.json。
- **vars 覆盖后左栏「视线」在正背卡/三视图里不生效**：这是版面技术需要（背面像不能看镜头），界面上该参数仍标「已用」。若要在 UI 明确提示，可在参数行加「本画幅被版面覆盖」标记。
- **九宫格不出人物信息文字**（见上）。如果一定要，建议把文字做成画面外部的后处理水印，而不是让模型画。
- **文字段仍是让模型直接画中文**：错字/异体字风险由模型决定；本轮只加了「简体中文、不写错字、单行不换行」和宽度/字号约束。
