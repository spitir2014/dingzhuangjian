## 1. 第二轮 P1 问题

### R1 [P1] 2view 负面「不要多画人」与「三处同一人 / 设定卡拼版」冲突

- **问题**：这张卡要求在同一个画面里画「大头像 + 正面全身 + 背面全身」三处同一个人；但负面写「不要多画人」，字面就是「不要画多个人」，与三处同人直接冲突。同一句还写「不要……照片拼贴」，而 format 写的是「设定卡拼版画面」，两个词在模型理解里很接近，可能把唯一正确的拼版方式也否定掉。
- **证据**：
  - data/layouts.json:18「……不要多画人、四宫格或照片拼贴；不要镜面翻转……」
  - data/layouts.json:10「一张 {{aspectText}} 设定卡拼版画面……」
  - data/layouts.json:22「画面左侧三分之一是同一个人的大头像……画面右侧三分之二并排同一个人的两张全身像……三处同一人……」
  - 该画幅是默认预设：data/presets.json:8「\"layoutId\": \"sheet_2view\"」、:11「\"recommended\": true」，即默认点开就是这张卡。
- **影响**：这是默认预设里唯一一句「数量级」的负面。模型可能：只画一个人（把三处合并成一张全身/半身）、拒绝多分格、或把「拼版」做成单张照片；即使画了三个，也可能因「不要多画人」而弱化全身像的存在。
- **建议改法（替掉该分句）**：

~~~
不要多画第四个人、不要画成四宫格，也不要做成没有分格的杂乱照片拼贴；画面里只允许这三个同一个人的形象（一个大头像、一张正面全身、一张背面全身）。
~~~

（三视图负面已经是「不要多画第四个人或四宫格」（layouts.json:44），2view 跟它对齐即可。）

### R2 [P1] 2view/3view 的「各占画面宽度约 24%~28%」把分格宽度写成了人物宽度

- **问题**：在 80% 画高下（2K 16:9 的 16:9 2K 人物高约 922px），人的肩宽通常只有约 10%~12% 画面宽；句子写成「各占画面宽度约 24%~28%」，如果模型按字面把人物画到 24%~28% 宽，就会得到肩宽约 2 倍正常值的矮胖体型。它本来想表达的是「每个分格占多宽 / 两个人之间留多少」，不是人物本身多宽。
- **证据**：
  - data/layouts.json:22「正面在左、中心在画面宽度 50%，背面在右、中心在 83%，各占画面宽度约 24%~28%，互不接触、不重叠，中间留约 6% 空隙」
  - data/layouts.json:48「人物中心分别在画面宽度 16.7%、50%、83.3%，各占画面宽度约 24%~28%……三张之间至少留 5% 空隙」
  - 2view 的「中间约 6%」与 24%~28% 也不自洽：中心距 33%，若各宽 24% 则空隙 9%；若各宽 28% 则空隙 5%。只有宽 27% 时才是 6%。
- **影响**：人物比例可能被拉宽；或模型把「各占」当成分格而不是人物，导致三个人物反而缩小、相互间距过大。两条 P1 合在一起，会直接影响默认卡的可读性。
- **建议改法（2view）**：

~~~
正面在左、中心在画面宽度 50%，背面在右、中心在 83%；两张各占画面宽度约 27%（含人物两侧留白，人物本身肩宽约画面宽度 11%），中间留约 6% 空隙，互不接触、不重叠。
~~~

- **建议改法（3view）**：

~~~
人物中心分别在画面宽度 16.7%、50%、83.3%，每张分格宽度约 27%（含两侧留白；人物本身肩宽约画面宽度 10%~12%），三张之间至少留 5% 空隙，互不接触、不重叠。
~~~

## 2. 第二轮 P2 问题

### P2-1 [portrait] 头高数字自相矛盾

- **证据**：data/layouts.json:97「头顶距画面上边约 14%，下巴约在画面高度 54%，头部（含头发）高度约占画面高度 40%~44%」。
- **推理**：头顶 14% + 头高 40% = 下巴 54%；若头高 44%，下巴应为 58%。两个数字不能同时成立。
- **影响**：模型可能取头高 44% 但把下巴压到 54%（头被压短），或反过来脸被拉长。
- **建议改法**：「头顶距画面上边约 14%，下巴约在画面高度 56%，头部（含头发）高度约占画面高度 42%」（或统一成 54% + 40%）。

### P2-2 [portrait] 负面缺「不要进入上方 12% 空白条」

- **证据**：2view/3view/fullbody 的负面都有「不要进入上方 12% 空白条」（layouts.json:18/44/70），portrait 负面（layouts.json:93）没有；但 portrait 版面（layouts.json:97）写了「头发与头顶都不进入」。
- **影响**：portrait 是四种里头顶离 12% 条最近的（下巴 54%），负面是最后一段，缺这句会降低约束权重。补一句即可。

### P2-3 [共用内容] 「可见毛孔」与全身体量冲突

- **证据**：data/templates.json:48「真实质感：可见毛孔与细小绒毛……眼神有自然高光与轻微红血丝。」这是四个画幅共用的内容段。
- **影响**：2view/3view/fullbody 的全身像只有约 900px 高，毛孔不可见；这句话会把模型推向放大面部/过度锐化皮肤，或让全身像出现不该有的皮肤特写。建议改成带尺度的表述（近景/肖像可见毛孔；全身像按实际比例缩小，不强行放大皮肤细节），或给全身像画幅用 vars 覆盖（需要给 realism 段加一个变量）。

### P2-4 [变量/UI] 2view/3view 的 gaze 被 vars 覆盖，左栏「视线」实际失效但 UI 仍标已用

- **证据**：layouts.json:25-27、51-53 用 `vars.gaze` 固定了视线文案；app.js:480-485 直接用覆盖值替换变量；app.js:570-577 的 usedVarKeys 仍把 {{gaze}} 记为已用，左栏参数行不会提示「本画幅被版面覆盖」。
- **影响**：用户把「视线」改成「垂眼/略偏」时，2view/3view 出图不变，但界面没有任何提示。建议在左栏/变量表加「本画幅由版面覆盖」标记，或把 gaze 从这两个画幅的 vars 里移出。

### P2-5 [数据] templates.json 与 layouts.json 两份四段文字仍完全相等，但校验不检查相等

- **证据**：当前两份文件的 format/style/negative/layout/vars/orient 完全一致；validate-data.mjs:155-158 分别调用 checkLayoutList，但没有「templates 与 layouts 必须相等」的检查；validate-data.mjs:219 的 orient 映射只读 templates.templates，不读 layouts.json（运行时实际读的是 layouts.json）。
- **影响**：改文案必须两处同步；若只改 layouts.json，校验仍会通过，但删掉 layouts.json 的回退路径会回到旧文案。orient 若两份不一致，presets 校验也会看错。建议在 validate 里加两份 equality 检查，并让 orient 校验读同一份（或要求两份相等）。

### P2-6 [3view] 侧面「一只眼睛与一只耳朵」没写哪只

- **证据**：data/layouts.json:48「鼻尖朝画面左侧……只看见一只眼睛与一只耳朵」。
- **影响**：既然已写「人物左侧面 + 鼻尖朝左」，按解剖应是左耳；但不写死，模型仍可能画右耳。建议补「（左耳）」；低风险。

### P2-7 [2view] 负面「照片拼贴」与正面「设定卡拼版」用词冲突（R1 的一部分）

- **证据**：layouts.json:10 vs :18。修 R1 时一并改成「没有分格的杂乱照片拼贴」，避免把「拼版」否定掉。

### P2-8 [3view] 侧面缺「双臂仍贴在身体两侧、不向前伸」

- **证据**：v1 建议的 A-pose 句含「侧面时双臂仍贴在身体两侧，不向前伸、不交叉」；落地后的 layouts.json:48（以及 :22、:74）没有这句，只剩「双臂与躯干夹角约 25~30 度」。
- **影响**：严格 90 度侧面时，A-pose 的手臂本来会与躯干重叠；没有这句，模型可能把近侧手臂画到身体前方，三视图的侧面轮廓与前/背面不一致。建议在 3view 版面补回「侧面时双臂仍贴在身体两侧，不向前伸、不交叉」。

### 9.1 压缩但语义未变（无需处理）

1. **info 段**（templates.json:60）：建议「……四周留白充足，绝不贴边、绝不出画、绝不被裁切……」→ 落地「……单行、不换行、不竖排、不写错字；不贴边、不出画、不被裁切、不被人物或头发遮挡」。删掉了「四周留白充足」与「绝不」的强调，新增「不写错字」；6%/8%/2.4%/≤80% 的几何与约束未变。
