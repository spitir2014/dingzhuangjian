本地运行的人物设定稿工作台：**随机一个人物 → 编译成结构化提示词 → 调用第三方生图接口 → 自动存档**。

名字取自影视的「定妆」——人物在镜头前的最终造型；这里把它做成一个本地工作台：参数、提示词、出图、存档都在同一页完成。

## 密钥配置（.env）

两种方式都行，密钥最终都只存在 `.env`：

1. **网页里填**：服务商弹窗的「密钥」框粘贴，保存时写进 `.env`，立即生效，重启也不会丢。
2. **手动改**：`ZXT_KEY_<服务商 id 大写>=密钥`，一行一个，改完重启定妆间。

变量名 = `ZXT_KEY_` + 服务商 `id`，**大写**，非字母数字一律换成下划线。当前默认的三条示例（以你的 `config.json` 为准，模板见 `.env.example`）：

| 服务商 id | `.env` 变量名 |
| --- | --- |
| `1fen` | `ZXT_KEY_1FEN` |
| `pmbcb27` | `ZXT_KEY_PMBCB27` |
| `mlgb7` | `ZXT_KEY_MLGB7` |

- **两类服务商共用同一套密钥规则**：生图服务商与「以图复刻」用的反推（LLM）服务商都按 `ZXT_KEY_<标识>` 读密钥，前端弹窗写密钥的路径也相同；两类标识不能重复。
- **缺密钥不会让服务起不来**：控制台打印 `[密钥缺失] …`，该服务商拉模型 / 出图 / 反推时明确报错并告诉你缺哪个变量。
- **密钥只写进 `.env`**：弹窗保存时由服务端替换/追加 `ZXT_KEY_<id>` 那一行，不会写进 `config.json`；弹窗里留空表示不改动已有密钥。
- **网页写密钥要同源**：`/api/providers/key` 只接受本机页面（`127.0.0.1` / `localhost`）发起的写入，其它网站跨站提交会被 403 拒绝。
- 测试或临时切换可以用环境变量 `ZXT_ENV` 指向另一份 `.env`、`ZXT_CONFIG` 指向另一份配置，互不干扰。
- **为什么不用 config.json 存**：它会被「拉模型 / 隐藏模型 / 改地址」反复重写，一旦写盘就多一份明文副本；现在 `saveConfig()` 统一剥掉 `apiKey`，任何路径都写不进去。
- **`ZXT_` 是历史前缀**（旧名 ZaoXiangTai 的缩写）：保留是为了已有 `.env`、测试与老存档不用迁移，与当前显示名「定妆间」无关；浏览器 `localStorage` 的 `zaoxiangtai.*` 同理。

## 启动

双击 `启动.bat`：

- **服务真正就绪之后**浏览器才自动打开 <http://127.0.0.1:8787>（不会再出现浏览器抢先打开、白屏或「无法访问此网站」）
- **这个黑窗口要保持开着**，关掉它 = 停止定妆间工作台；网页可以随便刷新、关掉再开
- 已经在运行时再双击一次：不会重复起服务，只会重新打开一次页面
- 起不来时窗口不会一闪而过，会停住并写明原因（没装 Node.js / 8787 端口被别的程序占用 / 服务报错）

也可以命令行：

    node server.mjs          # 只起服务，不自动开浏览器
    node server.mjs --open   # 起服务，并在就绪后自动打开浏览器

换端口用环境变量 `PORT`（例如先 `set PORT=9000`，再 `node server.mjs --open` 并访问 <http://127.0.0.1:9000>）；`ZXT_OPEN=1` 等同于 `--open`。

密钥来自 `.env`（网页弹窗里填的也会写进去，见上一节），`config.json` 只存地址与开关。默认示例里是三个服务商（实际以你的 `config.json` 为准，可在页面「服务商 → ⋯」里增删改）：

| 服务商名称 | `id` | 接口地址 | 模型 |
| --- | --- | --- | --- |
| 生图模型，可以图生图 | `1fen` | `https://api-image.shour.bond` | 由密钥决定，见管理面板 |
| 7里钱一张2k图 文生图 | `pmbcb27` | `https://api-image.shour.bond` | 由密钥决定，见管理面板 |
| mlgb7 | `mlgb7` | `https://image.mlgb7.com` | 由密钥决定，见管理面板 |

**模型列表是“按密钥”返回的**：同一个中转站，换一把密钥，`/v1/models` 返回的模型可能就不一样。
所以下拉里看到的名字不对时，先看「服务商」是不是切到了想用的那个、密钥是不是对应分组的。
同一服务商也能配多条（不同分组各一条），用「名称」区分即可。

首页右上角的「服务商」下拉里可以 **＋ 接入新的接口**。接口需要兼容 OpenAI 的：

- `GET  /v1/models`
- `POST /v1/images/generations`

「以图复刻」另接一类 **LLM 服务商**（不是生图服务商，单独一套列表），接口需要兼容 OpenAI 的：

- `GET  /v1/models`
- `POST /v1/chat/completions`——消息里用 `image_url` 传 base64 图片，所以模型必须支持图片输入（vision）

接口地址填 `https://host`、`https://host/v1` 或 `https://host/v1/models` 都行（会自动裁成 host 再拼路径）。
**密钥**：新增服务商时填一个「标识」（如 `cpa`，它决定 `.env` 里的变量名），弹窗里可以直接粘贴密钥；保存时会写进 `.env`（`config.json` 不保存），立即生效。

下拉里的模型名就是请求里真正发出去的模型 id（上游的 `display_name` 只放在悬停提示 / 管理面板里作备注）。
密钥只存在于本机 `.env`，页面只显示掩码。

## 画布缩放（滚轮）

中栏画布可以像看图软件一样放大看细节：

- **滚轮向上放大、向下缩小**，以鼠标所在位置为中心，范围 20%–800%
- 放大后**按住左键拖动**平移画面；图比画布大时贴边裁切，不会把图拖丢
- **双击画面**、点画布上方工具条里的 **「适应」**（或点倍数本身）立即还原成整张
- 工具条里的 `−` / `＋` 按钮给没有滚轮的触屏设备用；旁边实时显示当前倍数
- 100% = 整张适配画布，不是原始像素 1:1；换图、重新生成时自动回到 100%
- 滚轮只在鼠标位于画布上时生效，左栏参数、右侧提示词等处的滚动不受影响

看脸、手、左上角文字这些细节时，300%–800% 比较顺手。

## 整页缩放与收起左右栏

- **整页等比缩放**：顶栏、左右栏、画布、存档条随窗口一起变大变小，不是只有中间的图在变。基准是 1440 × 900（100%）；窗口更小整页缩小、更大整页放大，下限 72%、上限 160%
- **收起左栏 / 右栏**：两个按钮都贴着中缝——左栏标题右边的 `‹`、右栏标题左边的 `›`。收起后该栏完全隐藏，屏幕左/右边缘只留一条竖排把手（「人物参数」「提示词编排」），点它展开回来
- 快捷键：`[` 收/放左栏，`]` 收/放右栏（在输入框里打字时不会触发）
- 收起状态记在浏览器里，刷新后保持
- 点变量 / 点参数词句跳转时，目标栏如果正收着会自动展开
- 画布滚轮缩放以鼠标为锚点，整页缩放后依然对准鼠标位置

## 左栏参数 ⇄ 右侧提示词（映射）

右侧提示词里的 `{{变量}}` 就是左栏参数 / 顶栏设置在句子里的位置。为了让映射看得见：

1. **参数标题旁的变量名**：例如「身高 `{{height}}`」，一眼知道这一项对应哪个变量。
2. **参数词句行**：每项下面那行「→ 身高约 172 厘米」就是真正写进提示词的文字。点它可以跳到最终提示词里同一处并高亮；鼠标悬停整行会在右侧同步高亮。
3. **变量 chips**：展开右侧任意内容段，顶部一排 `{{变量}} 当前值`，点 chip 直接跳到左栏对应参数。
4. **解析预览**：每个内容段下方把 `{{变量}}` 替换成实际文字并高亮；鼠标悬停看「变量名 · 来源 · 当前值」。
5. **变量表**（右侧面板顶部）：列出当前提示词用到的全部变量、当前值、来源、用在哪些段落；可切「全部变量」，可搜索、可复制占位符。点一行跳到来源并在最终提示词里高亮。
6. **未用标记**：当前画幅模板没有引用的参数，词句行会变灰并标「未用」——提醒你改它不会影响提示词。

| 变量 | 实际内容 | 来源 |
| --- | --- | --- |
| `{{aspectText}}` | `16:9 横版` / `2:3 竖版` 这种画幅描述 | 顶栏「比例」+ 清晰度对应像素的横竖 |
| `{{aspectRatio}}` / `{{sizePx}}` | `16:9` / `2048x1152` | 顶栏「比例」「清晰度」 |

## 三方数据流与优先级

参数、变量、提示词这三份东西现在只有一条管线：左栏改的是**值**，段落里的 `{{变量}}` 是值的**落点**，最终提示词是这条管线唯一的**产物**。预览、复制、「生成」读的是同一份快照，不再各自拼一遍。

| 层 | 数据 / 入口 | 谁在生产 | 产物 |
| --- | --- | --- | --- |
| 参数层 | `data/params.json`（87 项）+ `data/eras.json`（时代包、36 张身份卡、9 个服饰槽位） | 左栏、顶栏、身份卡 | `state.params` 的一组取值（+ 当前 `lookId`） |
| 变量层 | `data/templates.json` / `data/layouts.json` 段落里的 `{{变量}}` | 右栏段落与画幅 `vars` | `buildVars()`：参数 id → 词句 |
| 提示词层 | 同一份快照 | 「最终提示词」/ 复制 / 发请求 | `buildPromptSnapshot()`：正文、段列表、字数、空值与未知变量清单 |

链路：

    左栏参数 + 顶栏设置 → {{变量}} → 提示词快照 → 预览 · 复制 · 发送

所有改值入口（改选项 / 单项掷 / 随机人物 / 换卡 / 切性别 / 切时代）都只走 `commitParams`，内部顺序固定；优先级就是下面这张表，高优先级可以盖掉低优先级：

| 顺序 | 层 | 说明 | 例子 |
| --- | --- | --- | --- |
| 1 | 硬约束 | 性别与选项门控、时代上下文，永远赢 | 女性不会长出络腮胡；「钿子」只对旗籍女性开放 |
| 2 | 锁定 | 你锁的项不被「随机人物」重掷 | 锁了身高，随机人物也不动它 |
| 3 | 派生 | 确定性联动，输给锁与身份卡 | 发型=剃发 → 发长=寸头、刘海与分缝=无 |
| 4 | 相关性 | 概率倾向，只改没锁的项 | 55 岁以上更容易花白 |
| 5 | 随机 | 剩余项按分性别权重掷 | 五官、记号、表情 |

被前几层拦下的调整不会静默吞掉：联动冲突进「体检 → 参数冲突」，被身份卡压住的锁进「体检 → 身份卡与解锁」。本轮改造的缺陷清单、设计取舍与验收命令见 [三方一致性修复说明](docs/04-验收与修复/三方一致性-修复说明-20261025.md)。

### 预览就是实际发送的

- 「最终提示词」面板、复制按钮、「生成」请求读的是同一份 `buildPromptSnapshot()`，**看到的就是发出去的**；存档 JSON 里的 `prompt` 也是这份文本，`promptHash` 用于事后比对。
- **空值不写进正文**：变量当前没有词句时替换成空串，不显示「（空）」占位符；一段如果因此没有任何文字，整段不输出。变量 chips 上仍会标「空」，悬停能看到「当前为空，不会输出文字」。
- **未知变量先剥掉再拦截**：写错变量名（例如 `{{hsirStyle}}`）不会随请求发出去，正文里直接移除；点「生成」会被拦下并提示先改，体检里也有「未定义变量」一栏。
- 换画幅、改段落、换身份卡之后不靠「生成一次」才算数：快照每次重算，字数与预算同步更新。

### 身份与卡片名

- `{{identity}}` 是**名词短语**，写进「左上角文字」那一行：`正一品文官`、`旗人贵妇`、`农妇`、`僧人`。它由时代 + 身份 + 品级 + 旗分 + 性别推导（`identityPhrase()`），不再取卡片名。
- **卡片名只留在卡片 UI 与证据里**：文官正一品·补服 / 晚清旗人贵妇·氅衣 这类名字用来挑卡、看考据，不进提示词——「·」会被模型当成画面里要写的字。
- 左上角那一行固定是「姓名 · 年龄岁 · 身高cm · 身份」，例如 `林长庚 · 34岁 · 178cm · 正一品文官`。
- 换成性别不同的卡（例如男卡换女卡）时，姓名、性格、简介会整套重生成，不会留男名配女卡；换卡改的是身份词，不是名字。
- 「随机人物」会连同**时代 / 身份卡 / 服饰槽位**一起换；想固定哪一层，就先把对应项锁上。

### 随机人物与服饰槽位

- 顶栏「随机人物」先随机性别与时代，再在锁定条件内挑一张身份卡，9 个槽位按卡填；卡没覆盖到的槽位在门控内随机。
- 想固定时代 / 旗分 / 身份 / 品级 / 场合或某个槽位，就先给该项上「锁」。「随机人物」只重掷**未锁**项；锁住的上下文会参与筛选身份卡，锁住的槽位会保留。
- 9 个槽位（首服 / 外衣 / 内搭 / 下装 / 鞋 / 配饰 / 纹样 / 质料 / 主色）也都提供「掷」和「锁」，可以逐项改。
- 「随机人物」可能落到「素体」（不穿衣）；想每次都出带服饰的人物，可以把「时代」锁到清·盛清 / 清·晚清。
- **时代=素体时 9 个槽位全部清空**，对应的 `{{headwear}}` 等变量输出空串，提示词里不会残留上一个时代的「暖帽」「补服」。
- 时代开着、9 个槽位全是「无」时，服饰句仍会输出身份行（「清代盛期文官」），不会出现「服装：。」。
- 门控不满足的选项置灰；非法值会被置空（回「无」），不会被悄悄重掷。

### 掷与种子的区别

| 动作 | 会变什么 | 种子 |
| --- | --- | --- |
| 参数行或选项上的「掷」 | 只重掷这一项，其它不动 | **不推进**：同一批状态下连点两次结果也不同，它按「种子 + 参数 + 第几次掷」算 |
| 顶栏「随机人物」 | 重掷所有未锁项（含时代 / 身份卡 / 服饰 / 姓名 / 档案），锁条件参与筛选 | 换一个新种子（toast 里能看到） |
| 种子行「掷」/「应用」 | 用（新 / 输入的）种子把未锁项重掷一遍（时代 / 身份卡 / 服饰也参与） | 「掷」换新种子、「应用」设为输入值 |
| 切性别 / 换卡 / 切时代 | 只重建与上下文相关的项 | 不变 |

- 「掷」不是复现入口：它**不改种子**，所以没法靠种子还原刚才那一下；要复现整批人就「应用」种子。
- 「应用」种子是按**锁**重建的：锁着的项保留你的取值，其余按种子掷。**种子 + 锁相同**即可复现；时代 / 身份卡 / 服饰也由种子和锁决定，改过锁或换过卡，同一种子也会掷出不同的人。
- **手动改过的派生项不会被立刻盖回来**：发长、刘海、分缝、身形这类由发型 / 体型派生出来的参数，手动「掷」或直接改值后会进入保护状态（`manualOverrides`），派生联动当次不再覆盖它；下一次「随机人物」或换卡会清掉这层保护，重新按硬约束与派生规则对齐。

### 锁定被硬约束覆盖时怎么看

- 锁只对「随机人物」和按种子重建生效，不是万能锁：性别硬约束、选项门控仍可能直接改掉它。
- 参数名旁出现「卡」= 这个参数当前由身份卡固定（悬停写着「由身份卡『卡名』固定」）；如果它同时又上了锁，锁会提示「身份卡优先」——「随机人物」会保留锁值并把这张卡标成自定义，手动换卡时才按卡片改；体检里可一键解锁。
- 体检里「身份卡与解锁」列出被卡压住的锁，点「解锁」解除这一项；解锁后在左栏重新掷/改值，会记为自定义，卡就不再压它。
- 派生被拦下时（例如锁了发长再选剃发）「参数冲突」会写「本应随…调成…，但被锁或身份卡挡住了」。

## 提示词编排

右侧每一段就是一个 Block，分三类：

- **结构段（4 段）**：画幅、版面、质感与光、不要出现。跟着顶栏「画幅」走——换画幅只换这 4 段，每个画幅改过的文字各自记住。版面还能做两件事：**改写**某几段内容段的取值（`vars`）、把某段在当前画幅**停用**（`suppress`），见下面「版面改写与停用段」
- **内容段（16 段）**：人物、人物档案、体量、比例与体态、面目、面部细节、面部进阶、毛发、皮肤与毛发、体表与毛发进阶、记号、真实质感、表情、着装、记忆点、左上角文字。**所有画幅共用同一份**，左栏 87 项人物参数永远都能在这里找到落点；改一次，切到哪个画幅都一样（个别画幅会按版面改写其中几段的取值）
- **自定义段**：自己点「＋ 加一段」加的，同样所有画幅共用

控制进不进最终提示词，就看**每段右上角的开关**：关掉不进提示词，再打开就回来。内置段不提供删除按钮——删掉整份提示词就缺块、也没有恢复入口；只有自定义段右上角有 `×` 可以移除。

拖拽把手 `⠿` 排序；改块里的文字时 `{{变量}}` 保持原样即可，写错变量名会红色标出。所有改动实时存在浏览器里。

- **竖版 = 发布展示**：肖像卡 3:4（小红书首图原生比例）、立绘 2:3 / 9:16；配方向中性的全身立绘 / 半身肖像。

## 画幅模板

顶栏「画幅」下拉切换画幅（正背设定卡 / 三视图 / 全身立绘 / 半身肖像 / 表情九宫格），下拉右边的 `⋯` 打开「画幅管理」：

- **＋ 新建画幅**：复制当前画幅的 4 个结构段，建完自动切过去并展开「版面」段，改成新画幅的取景即可
- **改名**：只改显示名，存档里记的 id 不变，老图不受影响
- **删除**：至少保留一个；删的正好是当前用的，自动切到第一个；已生成的存档不受影响
- **恢复默认**：回到出厂 5 个画幅，各画幅结构段改过的文字也回默认（人物内容段保留）

画幅只决定右侧**结构段**（画幅 / 版面 / 质感 / 负面）怎么写，人物内容段所有画幅共用一份。默认值来自 `data/templates.json`；你在界面上改过之后，整份列表会落到 `data/layouts.json`——**这个文件在就以它为准，删掉它就回到默认**，也可以直接手改再刷新。

### 版面改写（vars）与停用段（suppress）

有些版面对「共用内容段」有特殊要求，光改版面文案解决不了，所以画幅对象支持两个可选字段（`templates.json` 与 `layouts.json` 同结构）：

- `vars`：覆盖这一段内容在本画幅里的取值。表情九宫格用它把 `{{expression}} / {{intensity}} / {{gaze}}` 换掉——版面里已经按格写了九种表情，再把「单一表情」拼进提示词，模型会九格画成同一张脸；正背卡 / 三视图用它把视线改成「背面像只画后脑、不回头」。
- `suppress`：本画幅不参与拼装的段落 id。表情九宫格停用「左上角文字」：3×3 矩阵没有空白位置，文字排出场只会压在第一格脸上。
- `orient`：`landscape` / `portrait` / `square` / `any`。正背卡、三视图是 `landscape`（横向并排版面），九宫格是 `square`；顶栏比例里方向不符的选项会变灰，切画幅时也会自动把比例改到合法值。

界面上被停用的段会显示「本画幅不用」、开关点不动；被改写的段在提示词里看到的就是改写后的值。`vars` 的键必须是已存在的变量，`suppress` 只能写内容段 id，`npm run validate` 会检查 `templates.json` 和运行时的 `layouts.json` 两份。

> 这一版新增了 `/api/layouts` 接口，第一次用请把「启动.bat」关掉重开一次；没重启时页面会退回用 `templates.json` 里的 5 个默认画幅，其余功能不受影响。

## 批量生成多张随机人物

顶栏「张数」可选 1–10 张。点一次「生成」：

1. **每一张都会重新随机一个种子、生成一个完整新人物**（时代 / 身份卡 / 服饰也一起换；第 1 张也不复用当前人物；只生成 1 张时才用当前人物）
2. **服务端并发生成**：前端把这一批的 10 个任务一次性交给本机服务端（`POST /api/generate-batch`），服务端**同时向上游发起 10 个请求**；不是一张一张等
3. 服务端每画完一张就立即存档，并把进度逐行推回前端；状态栏实时显示「生成中 · 完成 3/10 张 · 进行中 7 张 · 失败 0 · 用时 40 秒」
4. 某一张失败不会中断整批：其余照常出图存档，最后状态栏汇总「失败 N 张（模型：错误原因）」
5. 生成中按钮变成「停 止」；停止只**停止派发新任务**，已经在飞的上游请求仍会画完并存档（详见下面「停止与超时」）
6. 生成过程中画布**不会被遮罩盖住**：画布左下角是一个状态胶囊（「生成中 · 完成 2/4 张 · 进行中 2 张 · 12 秒」），不挡图；随时可以点底部长条里的旧图翻看，不用等这批画完
7. 手动翻过旧图后，画布就不再自动跟着新图跳，工具条上会出现 **「↩ 回到最新」**；点它回到最近画完 / 最新存档的一张，之后继续自动跟随

并发说明：

- 为什么不是前端直接发 10 个请求：浏览器对同一个域名最多只保持 **6 个** HTTP/1.1 连接，10 个长请求会有 4 个排队。走服务端批量接口才能真正 10 路并发，也顺带省掉 10 次大图上传
- **按模型设并发上限**：`gpt-image-2.5-sunburst` 同时最多 **4 张**（账号少，10 张一起打容易把账号打到冷却）；seedream 两个模型仍是 10。上限写在 `server.mjs` 的 `MODEL_CONCURRENCY`，也可以在 `config.json` 里用 `settings.modelConcurrency` 覆盖（键是模型名，值是 1–10）
- 可调上限时状态栏会显示「并发上限 4 张」，其余任务在服务端排队，一张画完自动接下一张
- 一张 1–3 分钟；10 张并发通常 1–4 分钟出完（取决于上游排队和限流）
- 存档顺序是「完成顺序」，不是提交顺序；底部长条按保存时间倒序显示
- 生成过程中画布默认实时显示「最近画完的那张」；手动翻过旧图后不再抢画面（点「↩ 回到最新」恢复跟随）；整批结束后会切回**第 N 张**（左侧参数对应的人）
- 并发生成时，存档的编号分配、写文件、写 index.json 都在服务端串行锁里完成，不会抢同一个编号或把索引写坏

### 停止与超时

- **停止**（生成中按钮变成「停 止」）：只停止**派发新任务**——还没开始的排队任务不再发出；已经在飞的上游请求会继续跑完、出图、照常存档。停止后按钮和画布立刻解锁（不用等上游），服务端批次还在收尾；页面随后每 3 秒静默查一次这一批是否结束，结束后再刷新一次存档条，不会恢复忙碌状态、也不会重新遮住画布。
- **两档硬截止**：单次上游请求默认 **3 分钟**（`jobTimeoutMs`），单张「含重试与退避」的总预算默认 **4 分钟**（`jobDeadlineMs`）。哪一档超了就把这张按失败处理（状态栏汇总里写「上游超过 N ms 未响应」），不会把整个批次卡死；批次整体预算按「张数 ÷ 并发 × 单张总预算 + 60 秒」估算，页面到点会主动断开进度流并解锁。
- **超时之后**：超时的那一张算失败，其余任务不受影响；已经出图的照常存档。点画布上方「↻ 重试失败 N 张」会用原人物参数重试，不会重新随机人物。
- **服务重启**：批次记录只存在内存里，重启后旧批次消失（`GET /api/batch/active` 返回空数组）；重启前没画完的那几张不会补画，页面轮询发现 404 就按「批次已中断」解锁，已经画完的图仍在存档条里。
- **刷新页面**：**不会取消批次**，服务端在后台照常画完并存档。刷新后页面启动时会查 `GET /api/batch/active`，如果本机还有这一批没结束就自动接管：状态栏写明「本机还有一批在生成 x/y，开始于 hh:mm」，画布左下角状态胶囊显示「后台批次 · 2/4 · 12 秒」这种格式，按钮显示「停 止」，但**不锁画布、不加遮罩**，结束时 toast 提示并刷新存档条。生成中关掉页面、电脑睡眠同理，服务端不依赖页面，会把这一批画到结束或硬截止。

### 失败与重试

- 某一张失败不会中断整批；状态栏和 toast 会汇总「失败 N 张（模型：错误原因）」
- 失败张会留在画布上方出现 **「↻ 重试失败 N 张」** 按钮：点它用**原人物参数、原提示词**重试，不重新随机人物；重试成功后按钮自动消失
- 重试策略按错误类型分开（`server.mjs` 的 `callUpstreamImage`）：
  - 普通 429 / 5xx：等 1.5s / 4s / 10s 再试，最多 4 次
  - **账号池无号**（`No available compatible accounts` 等）：等 10s / 30s / 60s 再试，最多 4 次，期间状态栏会提示「上游账号池暂无可用账号」
- **仍然不会自动换模型**：失败就如实汇总，等上游恢复后点「重试失败」，或手动在顶栏换模型

### 遇到 `No available compatible accounts`

这是中转站账号调度器的报错，不是本程序的 bug：它对请求的模型按分组找“兼容账号”，当这些账号全部处于冷却 / 限流 / 额度耗尽 / 被禁用状态时就报这句话，通常几分钟到十几分钟自动恢复。

处理办法：

1. 等 1–5 分钟，点画布上方的 **「↻ 重试失败 N 张」**，不用重新编号/重新随机
2. 急着出图先换 seedream-5.0-pro / lite
3. 如果频繁出现：找中转服务商确认该模型分组的账号数与余额；或在 `config.json` 把该模型的并发上限调低（如 2）
4. 本地无法修复上游账号池问题，只能等、换模型或换服务商

## 模型与服务商管理

顶栏「⋯」打开管理面板：

- 服务商：查看地址与密钥掩码；没配密钥的会显示 **⚠ 未配置密钥（点「编辑」填入，或写 .env 的 ZXT_KEY_…）**；每行有 **编辑** 和 **删除**
  - 编辑可以改名称 / 接口地址 / 密钥；弹窗里填的密钥会写进 `.env`（`config.json` 不保存），保存后立即生效，留空表示不改
  - 点「编辑」会先收起管理面板再弹出编辑框（两个弹窗不叠在一起），**保存或取消后自动回到管理面板**；Esc 也能关
  - 改了地址或密钥、且改的是当前服务商，会自动重新拉一遍模型
  - 删除只删本地记录，不动上游
- 模型：当前服务商拉到的全部模型，可单独「隐藏 / 显示」
  - 隐藏只是从下拉里移除，不删上游（上游模型本来也删不掉）
  - 隐藏记录存在 config.json 的 hiddenModels 里

「↻」和面板里的「重新拉取」都是重新拉模型。**接口地址只填域名也行**（如 `https://api-image.shour.bond`）：
服务端会依次试 `{地址}/v1/models` 和 `{地址}/models`，命中哪个就把前缀记住（`config.json` 里的 `modelBase`），
生图接口沿用同一个前缀。路径不对（404 / 返回网页）才换下一条，401 / 429 / 5xx 这类与路径无关的错误立即如实上报。
像「画布中转」这种目录在 `/canvas/v1/models` 的，地址里要保留 `/canvas`。

## 参考图复刻（图 → 提示词 / 风格）

给一张参考图，用**视觉 LLM** 反推出一段相似的提示词和这一类风格；结果可以用两种方式回到出图链路：

1. **整段生成**：这次生成直接使用复刻出来的完整提示词，左栏人物参数与右栏段落都不参与（画布上方标签写「复刻提示词：…」）。
2. **套用到当前人物**：只把结果里的「风格与质感：」段追加到当前人物提示词末尾，人物仍由左栏参数决定（标签写「风格：…」）。

两种方式都只对**本次**生效，点画布上方的标签即可清除；生成请求会把 `style / externalPrompt` 记进存档 `promptMeta`，事后能查这次用的是哪条。

### 入口与流程

顶栏「以图复刻」：

- **参考图**：点击 / 拖入 / Ctrl+V 粘贴本地图片；也可以粘一个图片链接（由本机服务代抓，默认禁止本机 / 内网地址，上限 15MB，只收 png / jpeg / webp）。发出去之前统一缩到最长边 1536，省 token 也避开上游 base64 上限。
- **反推模型**：服务商列表是独立的 LLM 服务商（生图服务商不会出现在这里）；「＋」直接接入新 LLM 服务商，「↻」拉模型。
- **强度**：对应请求里的强度参数（默认 `reasoning_effort`，可在服务商弹窗里改参数名，填 `none` 表示不发）；选「自动」就不发。上游不认这个参数时会自动去掉再试一次，并在结果提示里注明「已自动忽略」。
- **系统提示词**：下拉选择；点「编辑」可以新建 / 改名 / 改文字 / 删除 / 恢复内置默认。选中哪条就用哪条。
- **额外要求**：可选的用户指令，和图片一起发给模型（例如「保留清代质感」「只写风格段」）。
- **结果**：反推文本可编辑；如果里面有 `风格与质感：` 段，会自动拆到下面的「风格段」框，套用到别的角色时只追加这一段。

### 保存为风格预设

「保存为风格预设」会把**名称、标签、完整提示词、风格段、缩略图、参考图来源、所用 LLM / 模型 / 系统提示词**写进 `data/styles.json`。弹窗底部列出所有预设，每条可以：

- **整段生成**：用这条预设的完整提示词生图
- **套用风格**：只把风格段追加到当前人物提示词
- **删除**

### 数据与接口

| 文件 / 接口 | 作用 |
| --- | --- |
| `data/reverse-prompts.json` | 系统提示词列表（`prompts[]` + `defaultId`）；没有文件时用内置默认 |
| `data/styles.json` | 风格预设列表 |
| `GET /api/reverse-prompts` | `{ ok, prompts, defaultId }` |
| `POST /api/reverse-prompts` | `{ id?, name, text }`；不传 id 是新建，传 id 是修改，`defaultId` 跟着选中项走 |
| `DELETE /api/reverse-prompts?id=` | 删除一条（至少保留一条） |
| `POST /api/reverse-prompts/reset` | 把内置那条恢复成出厂文字 |
| `GET /api/styles` / `POST /api/styles` / `DELETE /api/styles?id=` | 风格预设的列表 / 新建或修改 / 删除 |
| `POST /api/reverse` | `{ providerId, model, systemPrompt, imageDataUrl, instruction?, strength? }` → `{ ok, text, meta }`；只接受 LLM 服务商 |
| `POST /api/fetch-image` | `{ url }` → `{ ok, dataUrl, mime, bytes, width, height }`；默认拦截本机 / 内网地址 |
| `POST /api/providers`（`kind: "llm"`） | 新增 / 编辑 LLM 服务商，存进 `config.llmProviders`，与生图 `providers` 分开 |

密钥仍然只进 `.env`：新 LLM 服务商的标识会变成 `ZXT_KEY_<标识大写>`；`config.json` 只保存地址 / 名称 / `modelBase` / `strengthParam`。

### 人物参数 v3 新增了什么

这一版把左栏从 36 项补到 **55 项**，新增的 19 项都已经接进提示词，默认落在三个新内容段（「比例与体态」「面部细节」「皮肤与毛发」，每段都能单独关掉）：

- **比例与骨架**：头身比、肩型、腰线、腿型
- **体态与体表**：体态、手型、肤质、雀斑、肤色冷暖
- **面目**：面中、颧骨、瞳色、睫毛、眼下、唇色、酒窝
- **毛发**：发质、发量、发际线

另外给既有参数补了选项：眼型（丹凤 / 桃花）、表情（挑眉 / 抿嘴 / 冷笑）、发型（狼尾 / 低马尾 / 编发）、肤色（古铜 / 深棕）、纹身（右臂花臂 / 颈侧小字）、疤痕（右手背 / 左眉骨）、脸型（瓜子）、胎记（右颊 / 左肩）。

三个新内容段是内置段，所有画幅共用。旧浏览器里之前改过的内容段不会被覆盖——缺的新段会自动补在列表里，不需要重置；新参数会跟着「随机人物」一起随机，也能逐项「掷」「锁」。


### 时代与服饰（2026-10-25 新增）

左栏从 73 项补到 **87 项**、选项从 317 补到约 **430**：

- **时代与身份**（并入「身份」组）：时代 / 旗分 / 身份 / 品级 / 场合。选了「清·盛清」后，「服饰」组才会出现；身份卡是快捷入口，一张卡 = 一个身份 + 一个场合 + 9 个槽位。
- **服饰**（新分组）：首服 / 外衣 / 内搭 / 下装 / 鞋 / 配饰 / 纹样 / 质料 / 主色。槽位受门控约束（例如「钿子」只对旗籍女性开放、「明黄」只对帝后开放），不合法的值会置灰，手改出的非法值会被置空（回「无」），不会被「随机人物」悄悄重掷。
- **品级是修正层**：选「文官 + 正一品」，会自动写补子「仙鹤」、顶珠「红宝石」、朝珠资格，并在服饰句里补全；不需要为 9 品各做一张卡。
- **十张身份卡**：文官正一品·补褂 / 吉服 / 朝服、旗人贵妇·盛装、汉人士人妻、汉人平民男、商贾、农妇、衙役皂隶、僧人。数据在 `data/eras.json`，考据置信度与来源也在里面。
- **画幅裁剪**：半身像与表情九宫格只写首服与近颈配饰，不写下装和鞋（避免模型把镜头拉远）。
- **时代负向词**：选了时代后，提示词末尾会追加一条时代禁忌（例如「不要出现晚清大拉翅、花盆底、氅衣」），集中在 `data/eras.json`。
- **素体态零影响**：时代=素体时服饰句返回空串，提示词与改造前逐字一致（测试里有断言）。

> 调研明细（10 篇小红书样本、七条原则、Gap matrix、参数依据）见 [docs/02-服饰与人物数据/人物参数调研-20261022.md](docs/02-服饰与人物数据/人物参数调研-20261022.md)。

- **选项扩充**：脸型（方圆 / 梨形）、眼型（瑞凤 / 狐狸）、眉（野生 / 八字 / 远山）、发型（半束 / 锁骨 / 盘发）、表情（悲伤 / 恐惧 / 厌恶 / 哭）

所有参数新增三层说明：

- `note`：它管什么，鼠标悬停参数名可见。
- `impact`：它落在哪个内容段、和哪些参数联动。
- `desc`：选项级说明，选项按钮悬停可见；语义型选项（眼型/鼻型/唇形/脸型/发型/表情/记号）都写了，三态选项用 `phrase` 兜底。

#### 人物档案

左栏顶部新增「人物档案」卡，点开可编辑：姓名、身份、性格、标签（怪癖）、简介、风格关键词。身份/性格/标签/风格关键词会写进「人物档案」段；简介只进存档，不进提示词（避免图片里出现不可控长文字）。「随机人物」会重新生成整套档案。

#### 参数详情 / 词典 / 体检 / 预算

- **参数详情**：点参数名或 `{{变量}}` 打开，含 note、impact、全部选项说明、三性别可用性、用在哪些段，以及掷/锁/记忆点按钮。
- **参数词典**：左栏工具条「词典」，可搜 87 项参数，点一行跳到左栏。
- **体检**：检查参数冲突（圆脸配方下颌、寸头配长发等）、未接入变量、所在段已关闭的数量、提示词预算、记忆点数；冲突带「修正」按钮，只提示不静默改。
- **预算**：右下角提示词字数后显示本画幅预算；素体态单图 1800 / 多视图 2100；清装态单图 2000 / 多视图 2300（服饰句约 +100 字）。≤预算绿、超出琥珀、超出 400 字红。
- **画幅改写提示**：左栏参数被当前画幅的 `vars` 覆盖时，参数详情里会标「本画幅被版面改写」（例如九宫格的「表情」、正背卡/三视图的「视线」）。
- **搜索/筛选/折叠**：按参数名、选项、变量搜索；全部/核心/进阶/未用筛选；分组头点击折叠，刷新保持。服饰组折叠时，身份卡、来源卡和 9 个槽位一起收起；素体态的提示行也能收起。

#### 兼容与校验

- 旧 localStorage 里的内容段文字不会被覆盖；缺少的新段自动追加，新参数取默认值。
- 旧存档 JSON 可读；缺少的新字段用默认值补齐。
- `data/params.json` 升到 v4，新增 `tier / note / impact / desc` 与顶层 `conflictRules`。
- `npm run validate`：校验 id、默认值、分性别权重、bands、变量引用、冲突规则。
- `npm run check`：把五个画幅逐个按各自预设编译提示词，断言无残留变量、机位/平视齐全、九宫格九条表情、停用段未进提示词、长度不超各画幅预算。
- `npm run test:layouts`：不装浏览器，直接复用 `web/app.js` 的真实函数体跑「换画幅 / 老存档迁移 / 版面 vars / 停用段 / 方向联动」回归。

### 性别是硬约束，不是滑杆

界面上有明确的 **男 / 女 / 中性** 三个按钮。每个特征选项都带**分性别的权重**，权重为 0 就表示"在这个性别下不可能出现"，界面上会置灰划掉：

| --- | --- | --- | --- |

| 胡须·山羊胡 | ✅ | ❌ | 极低 |
| 胡须·短须 | ✅ | ❌ | 低 |
| 胡须·小绒毛 | — | ✅ | ✅ |
| 胸部·平坦/胸肌 | ✅ | ❌ | ✅ |
| 胸部·小巧/适中/丰满 | ❌ | ✅ | 极低 |
| 喉结·明显 | ✅ | ❌ | 低 |
| 体毛·浓密 | ✅ | ❌ | 低 |

### 气质 ≠ 性别

「气质」是**同一性别内的表达偏向**，不改生理结构：

- 男：35–100（清秀 ←→ 硬朗）
- 女：0–65（柔和 ←→ 英气）
- 中性：25–75

所以"英气的女人"和"清秀的男人"都存在，但都不会长出络腮胡。

### 切换性别时会发生什么

1. 数值参数按新性别的区间 **clamp**（身高、气质）
2. 当前值在新性别下不允许的选项 **自动重掷**
3. 姓名按新性别的字库 **重新生成**
4. 存档目录跟着变（男 / 女 / 中性）

**硬约束优先于锁定**：锁定只影响"随机人物"时是否重掷，不会让女性保留络腮胡。

### 素体遮挡

- 男：上身赤裸 + 肉色紧身短裤
- 女 / 中性：肉色抹胸 + 肉色紧身短裤

这样既不触发接口的裸露审核，也能看清体型。

## 参数与词库

参数定义在 `data/params.json`（v4）。每个参数除了 `phrase`（真正写进提示词的词句），还有 `tier`（核心/进阶）、`note`（管什么）、`impact`（影响画面哪里）；选项可选带 `desc`（长什么样）、`w`（分性别权重）。

- 加参数：在对应分组里加一条，`id / label / type / tier / note / impact / options(或 bands) / default`，再在 `data/templates.json` 的某个内容段里写 `{{id}}`，无需改代码
- 加画幅模板：改 `data/templates.json` 的 `templates` 和 `order`
- 加姓名/身份/性格/风格词库：改 `data/names.json`
- 改完先跑 `npm run validate` 和 `npm run check`

## 批次接口与超时设置

并发生成的进度、取消和刷新接管都靠服务端内存里的批次注册表（结束 `batchKeepMs` 后清理）：

| 接口 | 作用 |
| --- | --- |
| `GET /api/batch/active` | 本机还没结束的批次：`{ ok: true, batches: [快照...] }`，按开始时间升序。刷新 / 重开页面靠它自动接管 |
| `GET /api/batch/:id` | 单个批次快照：`{ ok: true, batch: { id, startedAt, finishedAt, total, concurrency, done, ok, fail, cancelledCount, active, jobs } }`；`jobs` 每项是 `{ idx, state, ms, code, error, file, rel }`（`state` 为 `pending` / `running` / `ok` / `fail` / `cancelled`）。没有这个 id 返回 404 `{ ok: false, error: "batch not found" }` |
| `POST /api/batch/:id/cancel` | 停止派发新任务：`{ ok: true, cancelled: true }`；已经在飞的上游请求照常画完存档。id 不存在返回 404 |

`POST /api/generate-batch` 的响应是 NDJSON，一行一个事件，页面边收边渲染：

    {"type":"batch-start","batchId":"b-lx2k9a-7f3d","total":4,"concurrency":2,"deadlineMs":540000}
    {"type":"job-start","idx":0}
    {"type":"heartbeat","batchId":"b-lx2k9a-7f3d","done":1,"ok":1,"fail":0,"active":1,"elapsedMs":5000}
    {"type":"job-done","idx":0,"ok":true,"file":"001_测试甲_170cm_正背设定卡.png","attempts":1,"ms":18000}
    {"type":"batch-done","batchId":"b-lx2k9a-7f3d","total":4,"ok":3,"fail":1,"cancelled":0,"elapsedMs":61000,"finishedAt":1729580000000}

中途出错还会推一条 `batch-error`。`config.json` 的 `settings` 里可以调几个超时 / 保留参数：

| 键 | 含义 | 默认值 |
| --- | --- | --- |
| `jobTimeoutMs` | 单次上游请求的超时 | `180000`（3 分钟） |
| `jobDeadlineMs` | 单张的总预算，含重试与退避 | `240000`（4 分钟） |
| `batchKeepMs` | 已结束批次在内存里保留多久 | `3600000`（1 小时） |
| `llmTimeoutMs` | 参考图反推单次 LLM 请求的超时（不重试，避免重复计费） | `180000`（3 分钟） |

本地联调 / 回归用假上游，**不调用真实上游、不花钱**：

    npm run test:batch

脚本会起一个本地假上游和一个临时 `server.mjs` 实例（临时 `config.json` 与输出目录，不碰真实存档），覆盖 ok / stall 超时 / cancel / 503 重试四组；`npm run test:reverse` 用同一个假上游的 `/v1/chat/completions` 跑「参考图复刻」契约。只想手动看一眼假上游：

    node scripts/mock-upstream.mjs --port 8801 --mode ok
    node scripts/mock-upstream.mjs --port 8801 --mode slow --delay 1500
    node scripts/mock-upstream.mjs --port 8801 --mode stall          # 永不响应，用来测超时，记得 Ctrl+C
    node scripts/mock-upstream.mjs --port 8801 --mode 503 --times 1

## 服务端接口（存档删除）

- `POST /api/archive/delete`：`{ items: [{ dir, file }] }`，把图片 + 同名 JSON 移到 `output/_回收站/人物/<性别>/`，并移除 index 条目；路径白名单校验，index 原子重写
- 回收站里的文件不会出现在页面存档条里，手动移回 `output/人物/<性别>/` 并在 index 里补一行即可恢复
- `POST /api/archive/open`：打开 `output/人物` 目录

## 已知情况

- `gpt-image-2.5-sunburst` 偶尔会返回 `No available compatible accounts` / `Upstream service temporarily unavailable`。选哪个模型就用哪个模型生成，失败不会自动换模型，状态栏会写明所选模型和真实错误。
- 左上角那行中文由模型直接绘制，**位置由模型决定**，偶发贴边。这一段的文字在「提示词编排 → 左上角文字」里，可以随时改。
- 一张图 30 秒到 4 分钟不等，复杂画幅更慢。
- 参考图反推的「强度」是可选参数：中转不认 `reasoning_effort` 时会自动去掉再试一次，结果不会有影响，只是少一层控制。
- 反推质量取决于你选的视觉模型和系统提示词；内置提示词只处理常见画面，换成你自己的复刻提示词更准。
- 图片链接由本机服务代抓：默认拦截 `127.0.0.1` / 内网段（防止 SSRF）；要抓本机图床只能走上传，或仅在测试时设 `ZXT_ALLOW_LOCAL_IMAGE_FETCH=1`。
